# Install Docker on the Modalix SoM DevKit

Docker lets you package an application with its dependencies and run it on the DevKit as a container. The Modalix SoM DevKit does not ship with Docker. This note shows two ways to install it on platform version 3.0: from the Palette SDK with one command, or by hand on the DevKit. Both install the same thing.

## Before You Start

You need:

- A Modalix SoM DevKit with platform version **3.0**. To check, run `cat /etc/buildinfo` on the DevKit.
- Internet access on the DevKit to download Docker.
- Free space on `/data`, where Docker keeps its images and containers. On the DevKit, `/data` is about 3 GB. Check the free space with `df -h /data`, and keep images small.

Container images for the DevKit must be built for `linux/arm64`.

## What the Installation Does

Both methods:

1. Install Docker CE (`docker-ce`, `docker-ce-cli`, and `containerd.io`) for ARM64 from Docker's Debian `trixie` repository.
2. Store Docker's data in `/data/docker`, and containerd's data in `/data/containerd`, so that images do not fill the root file system.
3. Turn on IP forwarding, which container networking needs.
4. Start the `docker` and `containerd` services, and start them at every boot.
5. Add your user to the `docker` group, so that you can run `docker` without `sudo`.

## Install from the Palette SDK {#palette-sdk}

Use this method if you develop in the Palette SDK and have paired the DevKit with it (`sima-cli sdk setup --devkit <devkit-ip>`). Pairing also gives the DevKit user passwordless `sudo`, which this method needs.

1. In the Palette SDK shell, run:

   ```console
   sdk$ dk container setup
   ```

   Answer `y` when it asks to set up Docker on the DevKit. To skip the question, run `dk container setup --yes`. If Docker already works on the DevKit, the command keeps it, and only adds your user to the `docker` group. If the installation is interrupted, run the command again; it resumes safely.

2. When it prints `Docker is ready on the DevKit`, run containers on the DevKit from the SDK shell:

   | Command | What it does |
   | --- | --- |
   | `dk container deploy <image> [docker-run-options] [-- command]` | Pulls the image from the SDK's local registry onto the DevKit, then runs it. |
   | `dk container run <image> [docker-run-options] [-- command]` | Runs an image that is already on the DevKit. |
   | `dk container pull <image>` | Pulls the image onto the DevKit. |
   | `dk container images` | Lists the images in the SDK's local registry. |
   | `dk container list` | Lists the containers on the DevKit. |
   | `dk container logs <container>` | Shows a container's output. Add `--follow` to keep watching. |
   | `dk container stop <container>` | Stops a container. |
   | `dk container remove <container>` | Removes a container. |

   For example, to build an image in the SDK for the DevKit, push it to the SDK's local registry, and start it on the DevKit:

   ```console
   sdk$ docker buildx build --platform linux/arm64 -t "$SIMA_CONTAINER_REGISTRY/my-app:latest" --push .
   sdk$ dk container deploy my-app:latest --detach --name my-app --network host
   sdk$ dk container logs my-app --follow
   ```

## Install by Hand on the DevKit {#manual}

Use this method if you do not use the Palette SDK. Run all commands below **on the DevKit**, through SSH or serial. `sudo` asks for your password.

1. Move the eLxr package mirror list aside while you install Docker. You put it back in step 9.

   ```console
   sima@modalix:~$ sudo mkdir -p /root/apt-disabled
   sima@modalix:~$ sudo mv /etc/apt/sources.list.d/0000mirror.list /root/apt-disabled/
   ```

2. Tell Docker to keep its data in `/data/docker`:

   ```console
   sima@modalix:~$ sudo mkdir -p /etc/docker /data/docker
   sima@modalix:~$ echo '{"data-root": "/data/docker", "firewall-backend": "nftables"}' | sudo tee /etc/docker/daemon.json
   ```

3. Turn on IP forwarding:

   ```console
   sima@modalix:~$ printf 'net.ipv4.ip_forward=1\nnet.ipv6.conf.all.forwarding=1\n' | sudo tee /etc/sysctl.d/99-docker-forward.conf
   sima@modalix:~$ sudo sysctl --system
   ```

4. Add Docker's package repository:

   ```console
   sima@modalix:~$ sudo install -m 0755 -d /etc/apt/keyrings
   sima@modalix:~$ sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
   sima@modalix:~$ sudo chmod a+r /etc/apt/keyrings/docker.asc
   sima@modalix:~$ echo 'deb [arch=arm64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/debian trixie stable' | sudo tee /etc/apt/sources.list.d/docker.list
   ```

5. Install Docker:

   ```console
   sima@modalix:~$ sudo apt-get update
   sima@modalix:~$ sudo apt-get install -y docker-ce docker-ce-cli containerd.io
   ```

6. Stop the services, and move containerd's data to `/data/containerd`:

   ```console
   sima@modalix:~$ sudo systemctl stop docker.socket docker containerd
   sima@modalix:~$ sudo mkdir -p /data/containerd
   sima@modalix:~$ sudo sh -c 'mv /var/lib/containerd/* /data/containerd/ 2>/dev/null; true'
   ```

7. Mount `/data/containerd` on `/var/lib/containerd` now and at every boot:

   ```console
   sima@modalix:~$ echo '/data/containerd /var/lib/containerd none bind 0 0' | sudo tee -a /etc/fstab
   sima@modalix:~$ sudo mount /var/lib/containerd
   ```

8. Start the services, and start them at every boot:

   ```console
   sima@modalix:~$ sudo systemctl enable containerd docker
   sima@modalix:~$ sudo systemctl restart containerd docker
   ```

9. Put the eLxr package mirror list back:

   ```console
   sima@modalix:~$ sudo mv /root/apt-disabled/0000mirror.list /etc/apt/sources.list.d/
   ```

10. Add your user to the `docker` group, then log out and log in again:

    ```console
    sima@modalix:~$ sudo usermod -aG docker "$USER"
    ```

## Check the Installation {#check}

On the DevKit:

1. Check that Docker keeps its data in `/data/docker`:

   ```console
   sima@modalix:~$ docker info --format '{{.DockerRootDir}}'
   /data/docker
   ```

2. Run a test container:

   ```console
   sima@modalix:~$ docker run --rm hello-world
   ```

   It prints `Hello from Docker!`.

3. Check the free space on `/data`:

   ```console
   sima@modalix:~$ df -h /data
   ```

   To free space, remove the images and containers you no longer need with `docker image prune` and `docker container prune`.
