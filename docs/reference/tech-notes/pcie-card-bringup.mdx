# PCIe Card Bring-up and Troubleshooting

Use this note when a Modalix HHHL PCIe card is detected by the host but the PCIe virtual Ethernet link does not come up — most often when the card is in an external Thunderbolt/USB4 enclosure.

:::note
Start with [PCIe Mode](/hardware/getting-started/pcie-mode) for hardware preparation and driver installation. Come back here when `sima-cli device discover` does not detect the virtual Ethernet link, or when it is detected but `ping` and SSH do not work.
:::

The PCIe stack provides a virtual Ethernet link between the host and the card, so `ping`, `ssh`, `scp`, and `iperf3` work over PCIe with no Ethernet cable:

```text
[HOST] 10.0.0.1/24  <--- PCIe --->  10.0.0.2/24 [MODALIX]
```

**[HOST]** is the Ubuntu machine and **[MODALIX]** is Linux running on the card.

## Power Sequence for External Enclosures

An external enclosure has its own power domain, so rebooting the host does not power-cycle the card.

- **Power off:** host first, then the enclosure.
- **Power on:** enclosure first, then the host.

Cards in internal motherboard slots share host power and need no special sequence.

## Interface Naming (Optional)

`sima-cli` resolves the PCIe virtual Ethernet interface from the card's PCI address in sysfs, so discovery works whatever the host has named the interface — usually a predictable name such as `enp47s0`. Renaming it is **not required**.

The rename is still useful if you want a stable interface name across hosts, and to keep NetworkManager from reconfiguring the link. To apply it, create two files on the **host**.

`/etc/udev/rules.d/90-network.rules`:

```text
SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="*:53:49:4d:41:30", NAME="veth-simaai", ENV{NM_UNMANAGED}="1"
```

`/etc/NetworkManager/conf.d/99-unmanaged-devices.conf`:

```ini
[device-vethsimaai-unmanaged]
match-device=interface-name:veth-simaai
managed=0
```

:::warning
Use the wildcard `*:53:49:4d:41:30` as written — do not substitute one system's exact MAC. The rule must match the **host** interface; the card's own interface ends in `:41:31`.
:::

The two files work together: the NetworkManager drop-in matches `interface-name:veth-simaai`, so it only takes effect once the `udev` rule has applied that name.

Apply the configuration:

```console
sima-user@sima-user-machine:~$ sudo udevadm control --reload-rules
sima-user@sima-user-machine:~$ sudo systemctl restart NetworkManager
```

The rule matches `ACTION=="add"`, so reloading alone does not rename an interface that already exists. Reconnect or power-cycle the enclosure so a new device event fires.

## Verify the Link

Check the address on each side. Substitute the host's own interface name if you did not apply the rename above:

<img src="/img/media/host-cli.png" alt="Run on the host machine" width="55" style={{float: 'left', marginRight: '8px'}} />

```console
sima-user@sima-user-machine:~$ ip -br addr show veth-simaai
veth-simaai   UNKNOWN   10.0.0.1/24
```

<img src="/img/media/devkit-cli.png" alt="Run on the Modalix card" width="55" style={{float: 'left', marginRight: '8px'}} />

```console
sima@modalix:~$ ip -br addr show veth-simaai
veth-simaai   UNKNOWN   10.0.0.2/24
```

Then confirm the path and discovery from the host:

```console
sima-user@sima-user-machine:~$ ping 10.0.0.2
sima-user@sima-user-machine:~$ ssh sima@10.0.0.2
sima-user@sima-user-machine:~$ sima-cli device discover
Detected PCIe virtual ethernet.
```

:::note
`UNKNOWN` is normal for virtual interfaces. If you applied the rename, the interface does not appear in **Settings → Network** because it is marked unmanaged — verify with `ip`, not the GUI.

Do not change the default `10.0.0.1` / `10.0.0.2` addresses unless SiMa engineering instructs you to.
:::

## Throughput Test

`sima-cli device discover` offers a throughput test across the virtual Ethernet path. It sets up both ends itself — no server needs to be started on the card:

<img src="/img/media/host-cli.png" alt="Run on the host machine" width="55" style={{float: 'left', marginRight: '8px'}} />

```console
sima-user@sima-user-machine:~$ sima-cli device discover
Detected PCIe virtual ethernet. Run throughput test now? [y/N]: y
Virtual Ethernet Throughput: 7.61 Gbps (healthy)
```

The tested setup measured roughly 7–8 Gbps. Actual throughput depends on the host, enclosure, and Thunderbolt path.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Card does not appear in `lspci -nnk -d 1f06:` | Enclosure power, Thunderbolt/USB4 connection, and card seating. Then cold power-cycle both host and enclosure. |
| `sima-cli` reports `veth-simaai not found` | An older `sima-cli` that still matched on the interface name. Update `sima-cli`, or apply the `udev` rule above and re-add or power-cycle the card. |
| Interface exists but `ping 10.0.0.2` fails | Confirm `10.0.0.1/24` on the host and `10.0.0.2/24` on the card, and that both interfaces are up. Do not change the addresses. |
| `Device "veth-simaai" does not exist` | Expected when the rename has not been applied, or on older pre-eLxr card builds that name the card-side interface `eth2`. Run `ip -br addr` and match on the address and the MAC ending `:41:30` (host) or `:41:31` (card). |
| PCIe worked before reboot, unstable after | Use the power sequence above — the enclosure has separate power. |
