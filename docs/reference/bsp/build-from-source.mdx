# Build the BSP from Source

Build the Modalix Linux kernel, U-Boot and device trees yourself, then install
the results on a board. Everything here uses public repositories — no NDA and no
sales enquiry.

:::note
Build from the source commit that matches the release running on your board.
[Release Compatibility](./release-compatibility.mdx) maps each platform release to
its kernel and U-Boot commit. See [Board Support Package](./index.md) for what a
BSP contains and where each repository lives.
:::

## Before You Start

- An **Ubuntu 22.04** host for the build.
- [Docker Engine](https://docs.docker.com/engine/install/ubuntu/) installed.
- `qemu-user-static` installed:

  ```console
  sima-user@sima-user-machine:~$ sudo apt install qemu-user-static
  ```

To install what you build, you also need a board already running an eLxr image
with root access, reachable over the network from the container, and booted from
eMMC (enumerated as `mmcblk0`).

## Set Up the Build Container

The SDK container carries the toolchain, headers and libraries for the target.
Download [`Dockerfile.modalix`](https://github.com/SiMa-ai/swsoc-simaai-elxr-doc/blob/master/Dockerfile.modalix),
then build the image from the directory that contains it:

```console
sima-user@sima-user-machine:~$ docker build -t modalix-sdk --file Dockerfile.modalix .
```

To preload extra packages into the sysroot, pass a comma-separated list:

```console
sima-user@sima-user-machine:~$ docker build --build-arg SDK_PKG_LIST=libzix-dev,vxi-dev -t modalix-sdk --file Dockerfile.modalix .
```

Launch it from a directory you can write to:

```console
sima-user@sima-user-machine:~$ docker run -it --privileged -v $(pwd):/data -w /data -v /dev:/dev --pid=host modalix-sdk
```

The sysroot is at `/opt/toolchain/aarch64/<platform>`. The build environment is
set automatically at launch; to set it by hand, run
`source /opt/bin/simaai-init-build-env modalix`.

## Build the Kernel

Inside the container:

```console
root@sdk:/data$ git clone https://github.com/SiMa-ai/simaai-linux.git && cd simaai-linux
root@sdk:/data/simaai-linux$ git checkout <kernel-commit>
root@sdk:/data/simaai-linux$ make ARCH=arm64 simaai_modalix_defconfig
root@sdk:/data/simaai-linux$ make all -j8 ARCH=arm64 LOCALVERSION="-modalix" DTC_FLAGS=-@
```

Replace `<kernel-commit>` with the kernel commit for your release from
[Release Compatibility](./release-compatibility.mdx). Building `master` gives you the
latest release, which may not match the image on your board.

This produces:

| Artifact | Path |
| --- | --- |
| Kernel image | `arch/arm64/boot/Image` |
| Device trees | `arch/arm64/boot/dts/simaai/*.dtb` |

## Build a Device Tree Overlay (Optional)

Write the overlay source (`.dtso`), then compile it to a blob (`.dtbo`):

```console
root@sdk:/data$ dtc -@ -I dts -O dtb -o imx415.dtbo imx415.dtso
```

## Build U-Boot

```console
root@sdk:/data$ git clone https://github.com/SiMa-ai/sima-ai-uboot.git && cd sima-ai-uboot
root@sdk:/data/sima-ai-uboot$ git checkout <u-boot-commit>
root@sdk:/data/sima-ai-uboot$ make ARCH=arm64 simaai_modalix_debug_defconfig
root@sdk:/data/sima-ai-uboot$ make all u-boot-initial-env V=1
```

Replace `<u-boot-commit>` with the U-Boot commit for your release from
[Release Compatibility](./release-compatibility.mdx). The image is `u-boot.bin`.

## Install the Artifacts

### How the eMMC Is Laid Out

| Partition | Contents |
| --- | --- |
| `mmcblk0p1` | U-Boot, primary |
| `mmcblk0p2` | U-Boot, backup |
| `mmcblk0p3` | Boot partition — holds two directories, `boot-0` and `boot-1`, one primary and one backup |
| `mmcblk0p4` | Root filesystem |

:::warning
Write partitions with `dd`, not `cp`, and copy to the board as `root`. To find
the board's address, run `hostname -I` or `ip route get 1.1.1.1` on the board.
:::

### U-Boot

Copy the image over, find the partition currently in use, and write it:

```console
root@sdk:/data$ scp sima-ai-uboot/u-boot.bin root@<board-ip>:/tmp/
```

```console
root@modalix:~# parted /dev/mmcblk0 print | grep legacy_boot | cut -f2 -d" "
1
root@modalix:~# dd if=/tmp/u-boot.bin of=/dev/mmcblk0p1 status=progress
root@modalix:~# sync
```

### Kernel, Device Trees and Overlays

Find the active boot directory first — it is either `boot-0` or `boot-1`:

```console
root@modalix:~# strings /boot/uboot.env | grep boot_path= | cut -f2 -d"="
/boot-0/
```

Copy the artifacts into that directory:

```console
root@sdk:/data$ scp simaai-linux/arch/arm64/boot/Image root@<board-ip>:/boot/boot-0/
root@sdk:/data$ scp simaai-linux/arch/arm64/boot/dts/simaai/modalix*.dtb root@<board-ip>:/boot/boot-0/
root@sdk:/data$ scp imx415.dtbo root@<board-ip>:/boot/boot-0/
```

### Kernel Modules

Modules go into the running kernel's module tree. `uname -a` on the board gives
the version string:

```console
root@sdk:/data$ scp simaai-linux/drivers/net/phy/marvell10g.ko root@<board-ip>:/lib/modules/6.18.3-modalix/kernel/drivers/net/phy/
```

### Finish Up

```console
root@modalix:~# depmod -a 6.18.3-modalix
root@modalix:~# sync
root@modalix:~# reboot
```

If you added a new overlay, register it in U-Boot's `dtbos` variable. Interrupt
autoboot, then:

```console
sima$ env set dtbos $dtbos imx415.dtbo
sima$ saveenv
sima$ boot
```

## Deploy Your Build

There are two ways to get a custom build onto a board, and they suit different
stages of work.

**Iterate on a running board.** While developing, copy the kernel image, device
trees, overlays and modules onto a board that already boots, as in
[Install the Artifacts](#install-the-artifacts), then reboot. This is the fastest
loop, but it changes one board by hand and leaves no reproducible image behind.

**Package an update for your boards.** To ship a build to other boards, including
in production, generate a board update package from your artifacts and flash that
package. Each board then carries exactly the same build, and you can reflash it
after every change.

:::caution[The update format changes in 3.0]
Platform releases 2.x and 3.0 use different update mechanisms: 3.0 moves to
swupdate. Build the update package in the format that matches the release on
your board. The steps for creating and flashing a custom update package are
being documented.
:::

[Firmware Update](/hardware/getting-started/firmware-update) installs the stock
SiMa.ai image. Use it to return a board to a known release, not to deploy your
own build: it overwrites what you installed.
