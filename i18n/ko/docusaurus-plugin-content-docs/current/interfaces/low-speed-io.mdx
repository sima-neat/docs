# 저속 I/O

Modalix에는 **전용 SPI 채널 2개**와 **구성 가능한 SIO 블록 8개**가 있습니다.
각 SIO 블록은 GPIO, UART, I2C 또는 SPI를 제공하도록 구성할 수 있으며, 출력 핀
멀티플렉서가 각 핀에 연결될 기능을 선택합니다.

## 매핑 지침

SIO 핀을 할당할 때는 다음 지침을 따르십시오.

1. 사용할 이더넷 및 PCIe 채널을 먼저 선택하십시오. 일부 핀 기능은 미리 정의되어
   있어 해당 PCIe 및 이더넷 인터페이스와 함께 사용해야 합니다.
2. 각 SIO 블록 내에서는 **위쪽 행의 핀이 우선**하므로 먼저 고려해야
   합니다.
3. 선택한 인터페이스가 핀에서 사용 가능한 기능과 일치하도록 **기능** 열에
   명시된 기능을 사용하십시오.

## GPIO

**드라이버:** `gpio-dwapb`

사용자 공간에서는 **libgpiod**와 해당 명령줄 도구를 사용합니다.

| 도구 | 용도 |
| --- | --- |
| `gpiodetect` | 사용 가능한 GPIO 칩 나열 |
| `gpioinfo` | 칩과 라인을 상태 및 소유 드라이버와 함께 나열 |
| `gpioset` | 라인 값 설정 |
| `gpioget` | 라인 값 읽기 |

먼저 칩과 라인을 확인하십시오. 장치는 `/dev/gpiochip0` 등의 이름으로
나타납니다.

```console
root@modalix:~# gpiodetect
root@modalix:~# gpioset gpiochip0 17 1
root@modalix:~# gpioget gpiochip0 17
```

사용자 지정 애플리케이션에서는 명령줄 도구를 호출하는 대신 **libgpiod C API**를
사용하십시오.

바인딩: [`snps,dw-apb-gpio.yaml`](https://github.com/SiMa-ai/simaai-linux/blob/master/Documentation/devicetree/bindings/gpio/snps,dw-apb-gpio.yaml)

## UART

**드라이버:** `snps-dw-apb-uart`

UART 노드 이름은 SIO 블록과 인덱스를 나타냅니다. `uart12`는 SIO 블록 1, 인덱스 2입니다.
각 SIO 블록은 최대 **4개의 UART 포트**를 제공하며 포트마다 핀 2개를 사용하므로,
인덱스 2는 출력 핀 4와 5에 매핑됩니다.

```dts
uart12: uart@0x0401a000 {
    compatible = "snps,dw-apb-uart";
    reg = <0x0 0x0401a000 0x0 0x100>;
    interrupts = <GIC_SPI 319 IRQ_TYPE_LEVEL_HIGH>;
    reg-io-width = <4>;
    reg-shift = <2>;
    clocks = <&sio10_clk SIMAAI_SIO_DEV_UART2>;
    resets = <&reset10 SIMAAI_SIO_DEV_UART2>;
    pinctrl-0 = <&pins_uart12_deafult>;
    pinctrl-names = "default";
    dmas = <&dmac10 4>, <&dmac10 5>;
    dma-names = "tx", "rx";
    status = "disabled";
};
```

오버레이에서 활성화합니다.

```dts
&uart12 {
    status = "okay";
};
```

클록, 리셋 및 기타 설정도 같은 오버레이에서 재정의할 수 있습니다. 각 SIO 블록은
위 노드에서 참조하는 자체 클록, 리셋, 핀 및 DMA 컨트롤러를 구현합니다.

바인딩: [`snps-dw-apb-uart.yaml`](https://github.com/SiMa-ai/simaai-linux/blob/master/Documentation/devicetree/bindings/serial/snps-dw-apb-uart.yaml)

## I2C

40핀 헤더(Waveshare 캐리어 카드의 J12)에는 I2C 인터페이스 2개가 노출되어
있습니다.

### 버스 확인

```console
root@modalix:~# ls /dev/i2c-*
/dev/i2c-0
/dev/i2c-1
```

### 40핀 헤더 핀아웃(J12)

| 핀 | 신호 | 핀 | 신호 |
| --- | --- | --- | --- |
| 1 | 3.3 V 전원 | 2 | 5 V 전원 |
| 3 | `I2C1_SDA` | 4 | 5 V 전원 |
| 5 | `I2C1_SCL` | 6 | GND |
| 7 | `GPIO09_AUD_MCLK` | 8 | `UART1_TXD` |
| 9 | GND | 10 | `UART1_RXD` |
| 11 | `UART1_RTS` | 12 | `I2S0_SCLK` |
| 13 | `SPI1_SCK` | 14 | GND |
| 15 | `GPIO12` | 16 | `SPI1_CS1` |
| 19 | `SPI0_MOSI` | 20 | GND |
| 21 | `SPI0_MISO` | 22 | `SPI1_MISO` |
| 23 | `SPI0_SCLK` | 24 | `SPI0_CS0` |
| 25 | GND | 26 | `SPI0_CS1` |
| 27 | `I2C0_SDA` | 28 | `I2C0_SCL` |
| 29 | `GPIO01` | 30 | GND |
| 31 | `GPIO11` | 32 | `GPIO07` |
| 33 | `GPIO13` | 34 | GND |
| 35 | `I2S0_FS` | 36 | `UART1_CTS` |
| 37 | `SPI1_MOSI` | 38 | `I2S0_SDIN` |
| 39 | GND | 40 | `I2S0_SDOUT` |

### 드라이버 및 디바이스 트리

I2C GPIO 익스팬더는 `arch/arm64/configs/simaai_modalix_defconfig`에서 활성화된
**PCF857x** 드라이버로 지원됩니다.

```text
CONFIG_GPIO_PCF857X=y
```

이 드라이버는 NXP PCF8574 및 PCF8575 I2C GPIO 익스팬더를 지원합니다.
[`simaai_modalix_defconfig`](https://github.com/SiMa-ai/simaai-linux/blob/master/arch/arm64/configs/simaai_modalix_defconfig)를 참조하십시오.
PCF8574가 연결된 버스 0을 활성화하는 예는 다음과 같습니다.

```dts
&i2c00 {
    status = "okay";
    clock-frequency = <400000>;

    pcf8574: gpio@27 {
        compatible = "nxp,pcf8574";
        reg = <0x27>;
        gpio-controller;
    };
};
```

### 명령줄 도구

`i2c-tools`는 표준 빌드에 포함되어 있습니다. 없으면 설치하십시오.

```console
root@modalix:~# apt update
root@modalix:~# apt install i2c-tools
```

바인딩: [`snps,designware-i2c.yaml`](https://github.com/SiMa-ai/simaai-linux/blob/master/Documentation/devicetree/bindings/i2c/snps,designware-i2c.yaml)
및 [`nxp,pcf8575.yaml`](https://github.com/SiMa-ai/simaai-linux/blob/master/Documentation/devicetree/bindings/gpio/nxp,pcf8575.yaml)

`i2cdetect`는 버스의 모든 주소를 탐색하고 응답하는 장치를 보고합니다.
`-r`은 SMBus 바이트 읽기 방식으로 탐색하고, `-y`는 확인 프롬프트를 건너뛰며, 마지막
인수는 버스 번호입니다.

```console
root@modalix:~# i2cdetect -r -y 0
```

## SPI

Modalix에는 SPI로 구성한 SIO 블록 외에도 전용 SPI 채널 2개가 있습니다. NVS SPI 및
SIO SPI 경로용 장치 오버레이와 SPI 장치 드라이버, 디바이스 트리 바인딩은 위의
UART에서 설명한 것과 동일한 오버레이 패턴을 따릅니다.
