# 네트워크 부팅 복구

탈착식 미디어가 아닌 네트워크를 통해 DevKit을 부팅해야 할 때 Net Boot 복구 기능을 사용하세요. 다음의 경우에 유용합니다.

- DevKit을 이전 버전의 SDK로 **다운그레이드**해야 합니다.
- 최신 버전이 아닌 빌드를 설치해야 합니다(예: 사전 릴리스 `develop` 빌드 또는 내부 엔지니어링 이미지).
- SD 카드 없이 파일 시스템이 손상된 보드를 복구해야 합니다. 네트워크 부팅에는 정상적으로 작동하는 U-Boot가 필요합니다.
- 새 보드를 도입하려 하시는데, 내부 저장 장치의 마모를 줄이고 싶으신 것 같습니다.
- 현재 Modalix DevKit을 Yocto Linux에서 eLxr로, 또는 eLxr에서 다시 Yocto Linux로 변환하고 있습니다. 변환에 필요한 구체적인 요구 사항은 [eLxr로 변환](/hardware/reference/tech-notes/elxr-conversion)를 참조하십시오.

:::note
이 가이드에서는 SiMa.ai에서 제공하는 펌웨어 이미지를 사용합니다. 직접 빌드한 이미지를 사용하려면 [eMMC에 이미지 기록](/hardware/deployment/flash-image)을 참조하세요.
:::

`sima-cli bootimg --netboot`를 실행하면 호스트의 내장 TFTP 서버가 대상 펌웨어를 제공합니다. 펌웨어 2.1.3 이상을 실행하는 DevKit 또는 PCIe 카드에 SSH로 연결할 수 있으면 호스트에서 U-Boot를 구성할 수 있습니다. 이전 펌웨어를 사용하거나 SSH로 연결할 수 없으면 3단계에서 시리얼 콘솔을 사용합니다.

<details open>
<summary><strong>1단계: 물리적 설정</strong></summary>

:::note
macOS 또는 Ubuntu Linux에서는 **sima-cli 2.1.21 이상**을 사용합니다. Windows에서는 **Windows Subsystem for Linux (WSL)**의 Ubuntu에 `sima-cli`를 설치하고 실행해야 합니다. 네이티브 Windows에서는 NetBoot를 지원하지 않습니다.

호스트 셸에서 TFTP 서버를 시작하고 eMMC에 이미지를 기록합니다. `--devkit`과 `--autoflash`를 사용하는 경우에도 별도의 시리얼 콘솔에서 네트워크 부팅 진행 상황을 확인하는 것이 좋습니다. 3단계에서 U-Boot를 수동으로 구성하려면 시리얼 콘솔이 필요합니다.
:::

1. **DevKit의 이더넷 포트**를 호스트 장치에 직접 연결하고, 호스트의 네트워크 인터페이스를 정적 IP 주소 **192.168.1.10**으로 설정합니다. Modalix 얼리 액세스 DevKit에서는 이더넷 포트 0을 사용합니다.

2. 시리얼 연결을 사용하려면 DevKit의 **UART 포트**를 호스트에 연결합니다. 호스트에 `sima-cli`를 설치한 후 시리얼 터미널을 엽니다.

   ```console
   sima-user@sima-user-machine:~$ sima-cli serial
   ```

   Windows에서는 Windows용 시리얼 클라이언트로 콘솔을 열 수 있습니다. [시리얼 연결](/hardware/getting-started/setup-serial)을 참조하세요.

3. DevKit에서 네트워크 인터페이스를 기본 정적 IP 주소인 **192.168.1.20**으로 구성합니다. 구성 방법은 [독립 모드 네트워크 설정](/hardware/getting-started/standalone-mode/network)을 따르십시오.

</details>

### Windows 호스트 {#windows-hosts}

보드에서 WSL 내부의 TFTP 서버에 연결할 수 있어야 합니다. Windows 11 22H2 이상에서는 LAN에서 직접 연결할 수 있도록 [WSL 2 미러링 네트워킹](https://learn.microsoft.com/en-us/windows/wsl/networking#mirrored-mode-networking)을 사용합니다. 이더넷으로 직접 연결할 경우 Windows에서 어댑터의 정적 IP 주소를 설정하고 보드와 연결된 인터페이스의 주소를 TFTP 서버 주소로 사용합니다. Windows와 Hyper-V 방화벽이 WSL로 들어오는 TFTP 트래픽을 허용하는지 확인합니다.

<details open>
<summary><strong>2단계. 호스트에서 TFTP Netboot 서버를 시작합니다.</strong></summary>

**요구 사항**

- 호스트와 DevKit는 동일한 물리적 네트워크 또는 직접 이더넷 연결을 통해 연결되어야 합니다.
- 기가비트 이상의 이더넷 연결을 사용합니다.
- 호스트는 펌웨어 이미지를 다운로드하기 위해 인터넷에 접속해야 합니다.
- UDP 포트 **69(TFTP)**는 호스트 방화벽에 의해 차단되어서는 안 됩니다.

`<version>`을 대상 펌웨어 버전(예: `%platform_version%`)으로, `<boardtype>`을 `modalix` 또는 `mlsoc`로, `<fwtype>`을 `yocto` 또는 `elxr`로 바꿉니다.

**macOS에서:**

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

**Ubuntu 또는 WSL의 Ubuntu에서**

:::warning
TFTP 서버는 권한이 필요한 포트 69에 연결되므로 `sudo` 명령어를 사용해야 합니다.
:::

```console
sima-user@sima-user-machine:~$ sudo "$(command -v sima-cli)" bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

### 호스트에서 NetBoot 구성(펌웨어 2.1.3 이상)

DevKit 또는 PCIe 카드가 펌웨어 2.1.3 이상을 실행 중이고 SSH로 연결할 수 있으면 `--devkit <ip>`를 추가하여 현재 IPv4 주소를 지정합니다. 이 옵션을 생략하면 `sima-cli`가 장치를 검색하며, 여러 장치가 검색되면 선택을 요청합니다. 재부팅을 승인하기 전에 장치와 TFTP 서버 주소를 확인합니다. CLI가 NetBoot로 재부팅하도록 예약했다면 3단계를 건너뜁니다.

네트워크 부팅 후 자동으로 기록하려면 `--autoflash`도 추가합니다.

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot --devkit <ip> --autoflash
```

Ubuntu 또는 WSL에서는 위와 같은 방식으로 `sudo`를 사용합니다. 네트워크 부팅이 완료되고 SSH 연결이 가능해지면 `--autoflash`가 이미지를 기록하고 eMMC로 부팅하도록 재부팅을 예약합니다. 원격 구성을 건너뛰었거나 CLI에 시리얼 콘솔을 사용한 수동 구성이 필요하다고 표시되면 TFTP 서버를 계속 실행하고 3단계와 4단계를 따릅니다.

이 명령은 다음 작업을 수행합니다.

1. 지정한 펌웨어와 보드 유형에 해당하는 부팅 파일과 기록용 이미지를 다운로드합니다.
2. 다음 NetBoot 세션에서도 재사용할 수 있도록 관리되는 캐시에 파일을 준비합니다.
3. TFTP 서버를 시작하고 `netboot.scr.uimg`를 포함한 부팅 파일을 제공합니다.

### 미리 다운로드한 펌웨어 이미지 사용

세션 중에 펌웨어를 다운로드하지 않고 NetBoot를 실행하려면 보드와 펌웨어 유형 옵션을 유지하고 `-v <version>`을 `--images <directory>`로 바꿉니다. eLxr의 경우 해당 디렉터리에 일치하는 최소 TFTP 아카이브와 압축된 eMMC 이미지(`.img.gz`)를 넣습니다. Yocto의 경우 릴리스 아카이브를 사용합니다. 세션이 끝난 후 CLI가 준비한 캐시를 삭제하려면 `--delete-cache`를 추가합니다.

</details>

<details open>
<summary><strong>3단계: DevKit 네트워크 부팅 설정</strong></summary>

2단계에서 `--devkit`으로 NetBoot 구성을 완료했다면 이 단계를 건너뜁니다. 그 외에는 아래의 시리얼 콘솔 절차를 따릅니다.

DevKit을 시리얼 콘솔을 통해 호스트에 연결한 상태에서 전원을 껐다가 다시 켜십시오. 전원 재부팅 중에 시리얼 콘솔 연결이 끊어지면 다시 연결하십시오. `Hit any key to stop autoboot` 메시지가 나타날 때까지 기다린 다음 아무 키나 눌러 U-Boot 셸로 들어갑니다.

```console
... ... ...

Address in DT is		ff:ff:ff:ff:ff:ff
Address in environment is	68:e1:54:00:05:c6
eth0: ethernet@a800000 [PRIME]
Hit any key to stop autoboot:  0
sima$
```

`sima-cli`가 수동 U-Boot 설정 명령을 출력했다면 해당 명령을 사용합니다. 그 외에는 1단계의 이더넷 직접 연결에 맞춰 보드와 TFTP 서버 주소를 설정한 후 호스트에서 부팅 스크립트를 불러옵니다.

```console
sima$ setenv ipaddr 192.168.1.20
sima$ setenv serverip 192.168.1.10
sima$ tftp ${scriptaddr} ${serverip}:netboot.scr.uimg && source ${scriptaddr}
```

다른 네트워크를 사용하는 경우 보드의 주소와 `sima-cli`에 표시된 연결 가능한 TFTP 서버 주소로 바꿉니다.

</details>

<details open>
<summary><strong>4단계: eMMC에 이미지 기록</strong></summary>

자동 기록이 시작되면 CLI에 기록 완료 및 재부팅 예약 메시지가 표시될 때까지 호스트 터미널과 네트워크 연결을 유지합니다. `netboot>` 프롬프트가 나타났지만 보드에 아직 이미지를 기록해야 한다면 아래의 수동 명령을 사용합니다.

호스트의 `netboot>` 프롬프트에서 다음 명령을 사용할 수 있습니다.

- `c` — TFTP 클라이언트, 연결 상태 및 확인 가능한 보드 정보를 표시합니다.
- `d` — 로컬 네트워크에서 장치를 검색합니다.
- `f [ip]` — 연결된 클라이언트의 eMMC에 이미지를 기록합니다. 보드의 현재 IPv4 주소를 지정하면 해당 보드를 직접 선택할 수 있습니다.
- `q` — 세션을 종료하고 TFTP 서버를 중지합니다.

DevKit의 네트워크 부팅이 끝나고 CLI에 SSH를 사용할 수 있다는 메시지가 표시될 때까지 기다립니다. 몇 분 정도 걸릴 수 있습니다.

호스트 터미널로 돌아가서 `netboot>` 프롬프트가 나타날 때까지 **Enter** 키를 누릅니다. 선택적으로 `c`를 입력하여 DevKit이 연결되었는지 확인하고 현재 펌웨어 버전을 표시한 다음, `f`를 입력하여 펌웨어를 업데이트합니다.

```console
netboot> f
```

다음과 유사한 로그를 확인할 수 있습니다.

```text
🔍 Checking SSH availability for 192.168.1.20...
✅ Board is online!
✅ SSH is available on 192.168.1.20
netboot> f
🔧 Initiating eMMC flash [...]
```

이미지 크기와 기록 시간은 펌웨어 릴리스에 따라 달라집니다. 다음은 진행 상황의 예입니다.

```text
↦ 520093696 bytes (520 MB, 496 MiB) copied, 1 s, 515 MB/s
↦ 5368709120 bytes (5.4 GB, 5.0 GiB) copied, 163.331 s, 32.9 MB/s
```

기록이 끝나면 eMMC로 부팅하라는 CLI의 재부팅 요청을 승인하거나 나중에 DevKit을 재부팅합니다. DevKit에서 `cat /etc/buildinfo`를 실행하여 대상 펌웨어 버전을 확인합니다.


</details>

<details open>
<summary><strong>문제 해결</strong></summary>

- DevKit가 네트워크 부팅에 실패하면 호스트와 장치가 동일한 서브넷(`192.168.1.x`)에 있는지 확인하십시오.
- Modalix 얼리 액세스 게시판에서는 네트워크 부팅을 위해 이더넷 포트 0만 지원됩니다.
- 호스트 방화벽이 **UDP 포트 69(TFTP)**를 허용하는지 확인합니다. WSL을 사용하는 경우 Windows와 Hyper-V 방화벽 설정도 확인합니다.
- DevKit과의 연결 상태를 확인하십시오.

  ```console
  modalix:~$ ping 192.168.1.10
  ```

- NetBoot 중에 DevKit의 IP 주소가 바뀌면 `sima-cli`가 이더넷 MAC 주소로 장치를 찾습니다. 자동 복구에 실패하면 `netboot>` 프롬프트에서 `d`를 사용하거나 시리얼 콘솔을 통해 보드에서 `ip -4 addr`를 실행합니다. 주소가 대상 보드의 것인지 확인한 후 현재 주소를 사용하여 기록합니다.

  ```console
  netboot> f <actual-ip>
  ```

- `f` 실행 시 준비된 eMMC 이미지가 없다고 표시되면 펌웨어 아카이브 또는 로컬 이미지 디렉터리에 기록용 이미지가 있는지 확인한 후 2단계의 명령을 다시 실행합니다.
- Modalix DevKit을 eLxr로 변환한 후 시리얼 콘솔에 NFS 관련 오류 메시지가 표시되면 안전하게 무시해도 됩니다.

</details>
