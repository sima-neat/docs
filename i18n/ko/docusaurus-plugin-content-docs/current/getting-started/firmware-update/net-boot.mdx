# 네트워크 부팅 복구

이동식 미디어가 아닌 네트워크를 통해 DevKit을 부팅해야 할 때 네트워크 부팅 복구 기능을 사용하세요. 다음의 경우에 유용합니다.

- DevKit을 이전 릴리스의 SDK로 **다운그레이드**해야 합니다.
- 최신 릴리스가 아닌 빌드를 설치해야 합니다(예: 사전 릴리스 `develop` 빌드 또는 내부 엔지니어링 이미지).
- 손상된 부트로더 또는 파일 시스템이 있는 보드를 복구해야 하는데, SD 카드가 없습니다.
- 새 보드를 브링업하려 하시는데, 내부 저장 장치의 마모를 줄이고 싶으신 것 같습니다.
- 현재 Modalix DevKit을 Yocto Linux에서 eLxr로, 또는 eLxr에서 다시 Yocto Linux로 변환하고 있습니다. 변환에 필요한 구체적인 요구 사항은 [eLxr로 변환](/hardware/reference/tech-notes/elxr-conversion)을 참조하십시오.

:::note
이 가이드는 SiMa.ai가 제공하는 이미지를 사용하며, 보드에서 U-Boot 프롬프트가 동작해야 합니다. 직접 빌드한 이미지를 설치하는 방법은 이 가이드에서 다루지 않습니다. 그 경우에는 [eMMC에 이미지 플래싱](/hardware/deployment/flash-image)을 참조하십시오.
:::

`sima-cli bootimg`와 함께 `--netboot` 옵션을 사용합니다. 그러면 대상 보드에 대한 부트 이미지를 다운로드하고 호스트에 내장된 TFTP 서버에서 해당 이미지를 제공합니다. DevKit은 이 TFTP 서버에서 부팅하고, `sima-cli`가 새 이미지를 eMMC에 플래싱합니다.

실행 방법은 두 가지입니다.

- **자동.** DevKit이 Linux로 부팅되고 호스트에서 SSH로 접속할 수 있으면, 명령 하나로 네트워크 부팅 설정, DevKit 재부팅, eMMC 플래싱까지 진행됩니다. 시리얼 콘솔은 필요하지 않습니다. [자동 네트워크 부팅 및 플래싱](#automatic)을 참조하세요.
- **수동.** DevKit이 Linux로 부팅되지 않거나 호스트에서 SSH로 접속할 수 없으면, 시리얼 콘솔을 통해 U-Boot에서 네트워크 부팅을 설정합니다. 1단계부터 4단계까지 따르세요.

## 자동 네트워크 부팅 및 플래싱 {#automatic}

`sima-cli` 2.1.17 이상이 필요합니다. 설치된 버전은 `sima-cli --version`으로 확인합니다.

1. **DevKit의 이더넷 포트**를 호스트에 직접 또는 스위치를 통해 연결합니다. 호스트에서 DevKit의 현재 IP 주소에 접근할 수 있는지 확인합니다(예: `ping 192.168.1.20`).

2. `--devkit`과 `--autoflash`를 지정해 `sima-cli bootimg`를 실행합니다. `<version>`은 대상 SDK 버전(예: `%platform_version%`)으로, `<devkit-ip>`는 DevKit의 현재 IP 주소로 바꿉니다.

   **macOS:**

   ```console
   sima-user@sima-user-machine:~$ sima-cli bootimg -v <version> --netboot --devkit <devkit-ip> --autoflash
   ```

   **Linux:** TFTP 서버는 권한이 필요한 포트 69에 바인딩되므로 `sudo`가 필요합니다.

   ```console
   sima-user@sima-user-machine:~$ sudo ~/.sima-cli/.venv/bin/sima-cli bootimg -v <version> --netboot --devkit <devkit-ip> --autoflash
   ```

   이 명령은 기본적으로 Modalix DevKit에 eLxr를 설치합니다. Yocto를 설치하려면 `--fwtype yocto`를 추가합니다. `--devkit`을 생략하면 `sima-cli`가 네트워크에서 DevKit을 찾아 어느 것을 사용할지 묻습니다.

3. `sima-cli`는 SSH로 DevKit에 접속하고, 사용할 네트워크 설정을 표시합니다. 설정을 확인한 뒤 승인합니다. 그러면 `sima-cli`는 다음을 수행합니다.

   1. DevKit의 U-Boot 환경을 저장하고, 호스트의 TFTP 서버에서 부팅하도록 설정합니다.
   2. DevKit을 재부팅합니다. 실행 중인 애플리케이션은 중단됩니다.
   3. DevKit이 네트워크에서 부팅되고 SSH를 사용할 수 있을 때까지 기다립니다.
   4. 이미지를 eMMC에 기록합니다.

   이 과정은 몇 분이 걸립니다. 명령을 계속 실행 상태로 두세요. 부팅 과정은 시리얼 콘솔로 볼 수 있지만, 꼭 그럴 필요는 없습니다.

4. `sima-cli`가 `✅ Flash completed`를 출력하면 `netboot>` 프롬프트에서 `q`를 입력합니다. `sima-cli`는 저장해 둔 U-Boot 환경을 DevKit에 다시 기록하여 DevKit이 다시 eMMC에서 부팅되도록 합니다.

5. DevKit의 전원을 껐다 켭니다. eMMC에서 대상 버전으로 부팅됩니다.

`sima-cli`가 SSH로 DevKit에 접속할 수 없거나 U-Boot 환경을 안전하게 변경할 수 없으면, DevKit을 변경하거나 재부팅하지 않습니다. TFTP 서버는 계속 실행되며, 입력할 U-Boot 명령을 출력할 수도 있습니다. [수동 네트워크 부팅 및 플래싱](#manual)의 3단계처럼 시리얼 콘솔에서 네트워크 부팅을 설정한 다음, 4단계처럼 `f`를 입력합니다.

## 수동 네트워크 부팅 및 플래싱 {#manual}

<details open>
<summary><strong>1단계: 물리적 설정</strong></summary>

:::note
이 절차는 **macOS** 및 **Ubuntu Linux** 호스트를 지원합니다.

호스트 시스템에 `sima-cli`가 설치되어 있지 않으면, 다음 단계를 진행하기 전에 설치하십시오.

터미널 세션 2개가 필요합니다.

1. DevKit에 연결된 시리얼 콘솔 세션을 사용합니다. 이 세션을 사용하여 U-Boot 환경 변수를 수정하여 DevKit이 네트워크를 통해 부팅되도록 합니다.
2. 호스트 셸 세션입니다. 이 세션을 사용하여 TFTP 서버를 시작하고 eMMC 플래싱을 시작합니다.
:::

1. **DevKit의 이더넷 포트**를 호스트 장치에 직접 연결하고, 호스트의 네트워크 인터페이스를 정적 IP 주소 **192.168.1.10**으로 설정합니다. Modalix 얼리 액세스 DevKit에서는 이더넷 포트 0을 사용합니다.

2. DevKit의 **UART 포트**를 호스트에 연결하여 콘솔에 액세스합니다. 호스트에 `sima-cli`를 설치한 후 시리얼 터미널을 엽니다.

   ```console
   sima-user@sima-user-machine:~$ sima-cli serial
   ```

3. DevKit에서 네트워크 인터페이스를 기본 정적 IP 주소인 **192.168.1.20**으로 구성합니다. 구성 방법은 [독립 실행형 모드 네트워크 설정](/hardware/getting-started/standalone-mode/network)을 따르십시오.

</details>

<details open>
<summary><strong>2단계. 호스트에서 TFTP 네트워크 부팅 서버를 시작합니다.</strong></summary>

**요구 사항**

- 호스트와 DevKit은 동일한 물리적 네트워크 또는 직접 이더넷 연결을 통해 연결되어야 합니다.
- 이더넷 연결은 기가비트 인터페이스 이상이어야 합니다(전송 속도는 1000Mbps를 초과해야 함).
- 호스트는 펌웨어 이미지를 다운로드하기 위해 인터넷에 접속해야 합니다.
- UDP 포트 **69(TFTP)**는 호스트 방화벽에 의해 차단되어서는 안 됩니다.

`<version>`을 대상 SDK 버전(예: `%platform_version%`)으로, `<boardtype>`을 `modalix` 또는 `mlsoc`로, `<fwtype>`을 `yocto` 또는 `elxr`로 바꿉니다.

**macOS에서:**

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

**Linux에서:**

:::warning
TFTP 서버는 권한이 필요한 포트 69에 연결되므로 `sudo` 명령어를 사용해야 합니다.
:::

```console
sima-user@sima-user-machine:~$ sudo ~/.sima-cli/.venv/bin/sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

이 명령어는:

1. 요청한 SDK 버전과 보드 유형에 맞는 부팅 가능한 이미지를 다운로드합니다.
2. 파일을 임시 작업 디렉터리에 추출합니다.
3. 로컬 TFTP 서버를 시작하고 추출된 부트 파일을 제공합니다(`Image`, `boot.scr`, `.dtb` 파일 등).

</details>

<details open>
<summary><strong> 3단계: DevKit을 네트워크 부팅으로 구성</strong></summary>

DevKit을 시리얼 콘솔을 통해 호스트에 연결한 상태에서 전원을 껐다가 다시 켜십시오. 전원 재부팅 중에 시리얼 콘솔 연결이 끊어지면 다시 연결하십시오. `Hit any key to stop autoboot` 메시지가 나타날 때까지 기다린 다음 아무 키나 눌러 U-Boot 셸로 들어갑니다.

```console
... ... ...

Address in DT is		ff:ff:ff:ff:ff:ff
Address in environment is	68:e1:54:00:05:c6
eth0: ethernet@a800000 [PRIME]
Hit any key to stop autoboot:  0
sima$
```

다음으로 U-Boot 셸에서 다음 명령을 실행합니다.

```console
sima:~$ setenv boot_targets net; saveenv; boot
```

Modalix **eLxr** 대상의 경우, 부팅하기 전에 cpio 이미지 이름을 설정하십시오.

```console
sima:~$ setenv cpio_name simaai-image-palette-modalix.cpio.gz; setenv boot_targets net; saveenv; boot
```

이 명령은 DevKit에 2단계에서 준비된 호스트 TFTP 서버에서 부팅하도록 지시합니다.

:::note
기본적으로 DevKit U-Boot는 다음과 같이 구성됩니다.

- `ipaddr=192.168.1.20`(DevKit의 이더넷 인터페이스, 멀티포트 보드의 첫 번째 포트).
- `serverip=192.168.1.10` (TFTP 서버를 실행하는 호스트 머신).

다른 네트워크를 사용하려면 U-Boot에서 `serverip` 및 `ipaddr`를 업데이트하여 현재 환경에 맞게 설정하십시오. 선택한 IP 주소에서 DevKit이 호스트에 연결할 수 있는지 확인하십시오.

```console
sima:~$ setenv serverip 10.0.0.10; setenv ipaddr 10.0.0.1; saveenv; boot
```
:::

</details>

<details open>
<summary><strong>4단계: eMMC를 플래싱합니다</strong></summary>

호스트의 `--netboot` 셸은 다음 명령을 지원합니다.

- `c` — 연결된 모든 클라이언트와 현재 해당 클라이언트에서 실행 중인 펌웨어 버전을 표시합니다.
- `d` — 네트워크에서 DevKit을 찾습니다.
- `f` — 선택한 클라이언트의 eMMC를 플래싱합니다.
- `q` — 세션을 종료하고 TFTP 서버를 중지합니다.

DevKit이 네트워크 부팅을 완료할 때까지 기다립니다. 이 과정은 몇 분 정도 걸릴 수 있습니다. 시리얼 콘솔에 로그인 프롬프트가 표시되면 보드가 준비된 것입니다. 전체 부팅 과정을 관찰하기 위해 시리얼 콘솔을 계속 연결해 두는 것이 좋습니다.

호스트 터미널로 돌아가서 `netboot>` 프롬프트가 나타날 때까지 **Enter** 키를 누릅니다. 선택적으로 `c`를 입력하여 DevKit이 연결되었는지 확인하고 현재 펌웨어 버전을 표시한 다음, `f`를 입력하여 펌웨어를 업데이트합니다.

```console
netboot> f
```

다음과 유사한 로그를 확인할 수 있습니다.

```text
🔍 Checking SSH availability for 192.168.1.20...
✅ Board is online!
✅ SSH is available on 192.168.1.20
netboot> f
🔧 Initiating eMMC flash [...]
```

이미지 파일의 크기는 대략 1.6GB이며, 전송하는 데 몇 분 정도 걸립니다. 예시 진행 상황은 다음과 같습니다.

```text
↦ 520093696 bytes (520 MB, 496 MiB) copied, 1 s, 515 MB/s
↦ 5368709120 bytes (5.4 GB, 5.0 GiB) copied, 163.331 s, 32.9 MB/s
```

플래싱이 완료되면 DevKit의 전원을 껐다가 다시 켜십시오. 그러면 eMMC에서 대상 버전이 부팅됩니다.

:::note
**네트워크 부팅 중에 DevKit의 IP 주소가 변경된 경우** (예: DHCP가 기본 주소인 `192.168.1.20` 대신 다른 주소를 할당한 경우) `f`는 자체적으로 보드에 연결하지 못합니다. DevKit의 시리얼 콘솔에서 새 IP 주소를 확인합니다. 이 주소는 부팅 로그에 출력되며, 네트워크 부팅된 셸에서 `ip addr`로 표시됩니다. 그런 다음 이 주소를 `f`에 명시적으로 전달합니다.

```console
netboot> f <new-ip>
```
:::

</details>

<details open>
<summary><strong>문제 해결</strong></summary>

- DevKit이 네트워크 부팅에 실패하면 호스트와 장치가 동일한 서브넷(`192.168.1.x`)에 있는지 확인하십시오.
- Modalix 얼리 액세스 보드에서는 네트워크 부팅을 위해 이더넷 포트 0만 지원됩니다.
- Linux 환경에서 호스트 방화벽이 **UDP 포트 69(TFTP)**를 허용하도록 설정되었는지 확인하십시오.
- DevKit과의 연결 상태를 확인하십시오.

  ```console
  modalix:~$ ping 192.168.1.10
  ```

- `f`에서 이미지를 찾지 못하면 2단계의 `sima-cli bootimg --netboot` 명령을 다시 실행하여 TFTP 경로를 새로 고칩니다.
- Modalix DevKit을 eLxr로 변환한 후 시리얼 콘솔에 NFS 관련 오류 메시지가 표시되면 안전하게 무시해도 됩니다.

</details>
