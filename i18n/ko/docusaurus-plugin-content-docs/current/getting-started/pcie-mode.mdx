# PCIe 모드

<Tabs>
<TabItem value="prereq" label="필수 조건" default>

:::note
계속하기 전에 `sima-cli`를 설치하거나 최신 버전으로 업데이트하십시오. 이 설명서는 최신 버전의 `sima-cli`와 함께 사용하기 위한 것입니다.
:::

시작하기 전에:

- 지원되는 호스트 플랫폼: Ubuntu 22.04 LTS.
- Windows 10/11 호스트 지원은 현재 베타 테스트 단계에 있습니다.
- 최적의 성능과 적절한 드라이버 기능을 위해 호스트 시스템의 UEFI/BIOS 설정을 구성하십시오.
  - 인텔 기반 시스템에서는 SRIOV, IOMMU 및 VT-D를 활성화합니다.
  - AMD 기반 시스템에서는 AMD-V를 비활성화하고 IOMMU를 활성화합니다.

</TabItem>
<TabItem value="hardware" label="하드웨어 준비">

![SiMa.ai MLSoC PCIe 카드의 PCIe DIP 스위치](/img/devkit/pcie-dip-switch.png)

1. MLSoC PCIe 카드에는 위와 같이 4개의 딥 스위치가 있습니다. 스위치 #1이 `OFF` 위치에 있는지 확인하십시오.
2. 실행/프로그램 스위치가 켜져 있는지 확인하십시오.
3. 호스트 장치의 전원을 끄고, DevKit을 PCIe 슬롯에 삽입한 다음, 호스트 장치의 전원을 켭니다.
4. Modalix 얼리 액세스 PCIe 카드에서 DIP 스위치를 공장 기본 설정 위치에 그대로 두십시오.
5. 호스트 마더보드가 주 슬롯(파란색)과 보조 슬롯(검은색) PCIe을 모두 제공하는 경우, SiMa PCIe 카드를 보조 슬롯(검은색)에 설치하십시오.
6. 카드의 시리얼/UART 커넥터를 호스트에 연결하여 초기 설정 및 디버깅을 수행하는 것이 좋습니다.
7. PCIe 카드는 네트워크에 직접 접속할 수 있도록 물리적인 이더넷 포트도 갖추고 있습니다.

DevKit의 인터페이스, 스위치 및 커넥터에 대한 자세한 내용은 [SiMa.ai DevKit 인터페이스](/hardware/devkit/modalix-ea-pcie)를 참조하십시오.

:::note
드물게 호스트 머신이 재부팅될 때 드라이버가 자동으로 로드되지 않아도 되는 경우, `/etc/modprobe.d/blacklist.conf` 파일을 생성하거나(이미 있는 경우 편집) 다음 줄을 추가하여 드라이버를 블랙리스트에 등록합니다: blacklist `sima_mla_drv`. 완료되면 `update-initramfs`를 실행하고 호스트 머신을 재부팅합니다. 재부팅 후에는 `insmod` 또는 `modeprobe`를 사용하여 드라이버를 수동으로 로드할 수 있습니다.
:::

</TabItem>
<TabItem value="driver-linux" label="드라이버 설치 (Linux)">

최신 드라이버를 설치하려면 Linux 호스트에서 다음 명령을 실행하세요.

```console
sima-user@sima-user-machine:~$ sima-cli install drivers/linux
... ... ...
=== Driver Installation Validation ===
  Component            | Status     | Details
  ----------------------------------------------------------------
  GStreamer            | PASS       | ✅ GStreamer plugin 'pciehost' installed
  Kernel Module        | PASS       | ✅ Kernel module 'sima_mla_drv' installed
  PCI Devices          | PASS       | ✅ Detected SiMa PCIe device(s):
  - 0000:04:00.0 Modalix HHHL v2              driver=sima_mla_drv

✅ Installation complete.
```

특정 드라이버 버전을 설치하려면 다음 플래그를 사용하세요: `-v`

```console
sima-user@sima-user-machine:~$ sima-cli install drivers/linux -v 2.1.0
```

:::note
드라이버 설치 후에는 검증을 진행하기 전에 호스트 장치의 전원을 껐다가 다시 켜 주세요.
:::

:::warning
**MLSoC PCIe 카드**에 대한 PCIe 드라이버 지원은 SDK 2.0.0에서 종료되었습니다. 위의 명령으로 설치된 드라이버는 **Modalix만** 지원합니다. MLSoC PCIe 카드를 사용하는 경우 `sima-cli install drivers/linux -v 2.0.0`을 사용하여 2.0.0 드라이버를 설치하십시오.
:::

## 가상 네트워크 {#virtual-network}

:::note
가상 네트워크 기능은 Linux 호스트의 펌웨어 버전 `1.5` 이상에서 사용할 수 있습니다. 이 기능을 사용하려면 DevKit이 최신 펌웨어 버전으로 [업데이트됨](/hardware/getting-started/firmware-update/)되었는지 확인하십시오.

이 기능은 Linux 호스트 시스템에서만 사용할 수 있습니다.
:::

PCI Express(PCIe)를 통해 호스트 시스템에 연결되면, SiMa.ai DevKit이 가상 이더넷 인터페이스를 설정합니다. 이 인터페이스는 고속 PCIe 버스를 통해 호스트와 DevKit 간의 직접적인 네트워크 통신을 가능하게 합니다.

가상 네트워크 기능은 주로 디버깅 목적으로 설계되었으며, 사용자가 다음과 같은 작업을 수행할 수 있도록 합니다.

- **안전 셸(SSH)**: 원격으로 DevKit의 명령줄 인터페이스에 접속하여 문제 해결 및 시스템 관리를 수행합니다.
- **안전한 파일 전송 프로토콜(SCP)**: 호스트와 DevKit 간에 파일을 안전하게 전송하여 개발 및 디버깅 과정에서 로그, 구성 파일 및 기타 필요한 파일을 이동하는 작업을 용이하게 합니다.

이 기능을 통해 사용자는 다음을 수행할 수 있습니다.

- **펌웨어 업데이트**: 파일 복사 방법을 따를 때 `scp` 및 `ssh` 유틸리티를 사용하여 펌웨어를 수동으로 업데이트합니다.
- **고정 IP 주소 할당(PCIe를 통한 이더넷)**: 호스트 장치/MLSoC 장치에 대해 고정 IP 주소를 수동으로 구성합니다.

기본적으로 `10.0.cardnum.1` 주소가 호스트 머신에 할당되고 `10.0.cardnum.2`가 MLSoC 장치에 할당됩니다. 그러나 안정적이고 일관된 네트워크를 위해서는 모듈을 로드할 때 모듈 매개변수 `default_ip=false`를 전달하여 호스트 인터페이스에 할당되는 기본 IP 주소를 비활성화해야 합니다.

모듈이 이미 로드된 경우, 아래와 같이 모듈을 제거한 다음 `default_ip=false` 매개변수를 사용하여 다시 로드합니다.

```console
sudo modprobe -r sima_mla_drv
sudo modprobe sima_mla_drv default_ip=false
```

**지속적인 구성**

시스템 재부팅 시에도 `default_ip=false` 설정이 유지되도록 하려면 다음 단계를 따르세요.

1. 필요한 옵션이 포함된 modprobe 구성 파일을 만듭니다.

   ```console
   echo "options sima_mla_drv default_ip=false" | sudo tee /etc/modprobe.d/sima_mla_drv_options.conf
   ```

2. 새 구성이 포함되도록 초기 RAM 파일 시스템을 업데이트합니다.

   ```console
   sudo update-initramfs -u
   ```

3. 변경 사항을 적용하려면 호스트 머신을 재부팅하세요.

   ```console
   sudo shutdown -r now
   ```

4. 시스템을 재시작한 후, 해당 매개변수가 올바르게 설정되었는지 확인합니다.

   ```console
   cat /sys/module/sima_mla_drv/parameters/default_ip
   ```

**수동 IP 주소 할당**

모듈을 수동으로 로드할 때(즉, `insmod`를 사용할 때) 아래 명령을 사용합니다. 이렇게 하면 호스트 시스템 인터페이스에 정적 IP 주소를 수동으로 할당하고, 결과적으로 MLSoC 장치에도 할당할 수 있습니다.

```console
sudo insmod sima_mla_drv.ko default_ip=false
```

또한 호스트 머신에 `ifconfig` 유틸리티가 설치되어 있어야 합니다.

```console
ifconfig <eth interface> 20.1.2.1
```

호스트 인터페이스에 IP 주소가 할당되면, SoC 인터페이스에 자동으로 IP + 1이 할당됩니다. 예를 들어, `20.1.2.1`이 호스트 머신에 할당되면, MLSoC의 IP는 `20.1.2.2`가 됩니다.

인터페이스가 생성될 때, 호스트 인터페이스는 `cardnum:S:I:m:A:0` 형식의 MAC 주소를 가지며, SoC 인터페이스는 `cardnum:S:I:m:A:1`의 MAC 주소를 가집니다. IP 주소는 생성 시 `host:10.0.cardnum.1` 및 `soc:10.0.cardnum.2`로 할당됩니다. 또한, 호스트 머신에 `ifconfig` 유틸리티가 설치되어 있어야 합니다.

1. 호스트 머신에서 `ifconfig` 명령의 출력 결과:

   ```console
   enp2s0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 65536
       inet 10.0.0.1  netmask 255.255.255.0  broadcast 10.0.0.255
       inet6 fe80::253:49ff:fe4d:4130  prefixlen 64  scopeid 0x20<link>
       ether 00:53:49:4d:41:30  txqueuelen 1000  (Ethernet)
       RX packets 14107  bytes 4460994 (4.4 MB)
       RX errors 0  dropped 0  overruns 0  frame 0
       TX packets 818  bytes 74840 (74.8 KB)
       TX errors 0  dropped 0 overruns 0  carrier 0  collisions 0
   ```

2. `ifconfig` 명령의 출력 결과 (SiMa.ai DevKit에서):

   ```console
   eth2: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 65536
       inet 10.0.0.2  netmask 255.255.255.0  broadcast 10.0.0.255
       inet6 fe80::253:49ff:fe4d:4131  prefixlen 64  scopeid 0x20<link>
       ether 00:53:49:4d:41:31  txqueuelen 1000  (Ethernet)
       RX packets 818  bytes 74840 (73.0 KiB)
       RX errors 0  dropped 0  overruns 0  frame 0
       TX packets 14109  bytes 4461636 (4.2 MiB)
       TX errors 0  dropped 0 overruns 0  carrier 0  collisions 0
   ```

3. 호스트에서 장치로 SSH를 사용하여 연결합니다. 기본 사용자 이름 `sima`와 비밀번호 `edgeai`를 사용하세요.

   ```console

   ED25519 key fingerprint is SHA256:ulxwiRM+cCQNJ90R5Qn5eV+9hqvkVNo0eWQ9pY3l8E0.

   Warning: Permanently added '10.0.0.2' (ED25519) to the list of known hosts..
   sima@10.0.0.2's password:
   sima@davinci:~#
   ```
