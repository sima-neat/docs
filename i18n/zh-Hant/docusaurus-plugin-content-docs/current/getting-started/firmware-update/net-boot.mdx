# 網路啟動恢復

當您需要透過網路啟動 DevKit，而不是從可移除媒體啟動時，請使用網路啟動恢復功能。這在以下情況下很有用：

- 您需要將 DevKit 降級到較舊版本的 SDK。
- 您需要安裝一個**不是最新版本**的建置版本（例如，預發布的 `develop` 建置版本或內部工程映像檔）。
- 您需要修復一個損壞了開機載入程式或檔案系統的板子，但沒有可用的 SD 卡。
- 您正在進行新板卡的硬體啟動，並希望避免內部儲存裝置耗損。
- 您正在將一個 Modalix DevKit 從 Yocto Linux 轉換為 eLxr，或者從 eLxr 轉換回 Yocto Linux。請參閱 [轉換為 eLxr](/hardware/reference/tech-notes/elxr-conversion)，以了解轉換所需的特定先決條件。

:::note
本指南使用 SiMa.ai 提供的映像檔，且電路板上必須有可運作的 U-Boot 提示字元。本指南不說明如何安裝您自行建置的映像檔；若有此需求，請參閱[將映像檔燒錄到 eMMC](/hardware/deployment/flash-image)。
:::

使用 `--netboot` 選項搭配 `sima-cli bootimg`。它會下載目標板的啟動映像檔，並從主機上的內建 TFTP 伺服器提供該映像檔。DevKit 接著從該 TFTP 伺服器啟動，再由 `sima-cli` 將新的映像檔燒錄到 eMMC。

有兩種執行方式：

- **自動。** 如果 DevKit 能啟動 Linux，且主機可以透過 SSH 連線到它，只要一個指令就能設定網路啟動、重新啟動 DevKit，並燒錄 eMMC。不需要序列主控台。請參閱[自動網路啟動與燒錄](#automatic)。
- **手動。** 如果 DevKit 無法啟動 Linux，或主機無法透過 SSH 連線到它，請透過序列主控台在 U-Boot 中設定網路啟動。請依照步驟 1 到步驟 4 操作。

## 自動網路啟動與燒錄 {#automatic}

需要 `sima-cli` 2.1.17 或更新版本。執行 `sima-cli --version` 可查看已安裝的版本。

1. 將 **DevKit 的乙太網路連接埠**直接或透過交換器連接到主機。確認主機可以連到 DevKit 目前的 IP 位址，例如 `ping 192.168.1.20`。

2. 加上 `--devkit` 和 `--autoflash` 執行 `sima-cli bootimg`。將 `<version>` 替換為目標 SDK 版本（例如 `%platform_version%`），並將 `<devkit-ip>` 替換為 DevKit 目前的 IP 位址。

   **在 macOS 上：**

   ```console
   sima-user@sima-user-machine:~$ sima-cli bootimg -v <version> --netboot --devkit <devkit-ip> --autoflash
   ```

   **在 Linux 上：** TFTP 伺服器會綁定到需要權限的連接埠 69，因此需要 `sudo`：

   ```console
   sima-user@sima-user-machine:~$ sudo ~/.sima-cli/.venv/bin/sima-cli bootimg -v <version> --netboot --devkit <devkit-ip> --autoflash
   ```

   此指令預設會在 Modalix DevKit 上安裝 eLxr。若要安裝 Yocto，請加上 `--fwtype yocto`。如果省略 `--devkit`，`sima-cli` 會在網路上尋找 DevKit，並請您選擇其中一台。

3. `sima-cli` 會透過 SSH 連線到 DevKit，並顯示它將使用的網路設定。確認設定後再同意。接著 `sima-cli` 會：

   1. 儲存 DevKit 的 U-Boot 環境，並將其設定為從主機上的 TFTP 伺服器啟動。
   2. 重新啟動 DevKit，這會中斷正在執行的應用程式。
   3. 等待 DevKit 從網路啟動完成，且可以使用 SSH。
   4. 將映像檔寫入 eMMC。

   這需要幾分鐘。請讓指令持續執行。您可以開啟序列主控台觀察啟動過程，但這不是必要的。

4. 當 `sima-cli` 顯示 `✅ Flash completed` 時，在 `netboot>` 提示字元輸入 `q`。`sima-cli` 會將儲存的 U-Boot 環境寫回 DevKit，讓它再次從 eMMC 啟動。

5. 將 DevKit 重新上電。它會從 eMMC 啟動目標版本。

如果 `sima-cli` 無法透過 SSH 連線到 DevKit，或無法安全地變更 U-Boot 環境，就不會變更或重新啟動 DevKit。TFTP 伺服器會繼續執行，並可能顯示需要輸入的 U-Boot 指令。請依照[手動網路啟動與燒錄](#manual)的步驟 3，透過序列主控台設定網路啟動，然後依照步驟 4 輸入 `f`。

## 手動網路啟動與燒錄 {#manual}

<details open>
<summary><strong>步驟 1：實體設定</strong></summary>

:::note
此程序支援 **macOS** 以及 **Ubuntu Linux** 主機。

如果您尚未在您的主機上安裝 `sima-cli`，請在繼續之前先安裝。

需要兩個終端機工作階段：

1. 連接到 DevKit 的序列主控台。使用此主控台來修改 U-Boot 環境變數，以便 DevKit 透過網路啟動。
2. 一個主機的 Shell 工作階段。使用這個工作階段來啟動 TFTP 伺服器，並開始 eMMC 燒錄。
:::

1. 將 **DevKit 的乙太網路連接埠** 直接連接到主機，並將主機的網路介面設定為靜態 IP 位址 **192.168.1.10**。在 Modalix 搶先體驗版 DevKit 上，使用乙太網路連接埠 0。

2. 將 DevKit 的 **UART 連接埠**連接到主機，以便進行主控台存取。在主機上安裝 `sima-cli` 後，開啟一個序列終端：

   ```console
   sima-user@sima-user-machine:~$ sima-cli serial
   ```

3. 在 DevKit 上，按照 [獨立模式網路設定](/hardware/getting-started/standalone-mode/network) 的步驟，將網路介面設定為預設的靜態 IP 位址 **192.168.1.20**。

</details>

<details open>
<summary><strong>步驟 2：在主機上啟動 TFTP Netboot 伺服器。</strong></summary>

**需求**

- 主機和 DevKit 必須位於相同的實體網路或直接乙太網路連線中。
- 乙太網路連線必須是 Gigabit 介面或更快的介面（傳輸速率大於 1000 Mbps）。
- 主機需要連線到網際網路才能下載韌體映像檔。
- UDP 埠 **69 (TFTP)** 不得被主機的防火牆封鎖。

將 `<version>` 替換為目標 SDK 版本（例如 `%platform_version%`），將 `<boardtype>` 替換為 `modalix` 或 `mlsoc`，並將 `<fwtype>` 替換為 `yocto` 或 `elxr`。

**在 macOS 上：**

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

**在 Linux 上：**

:::warning
TFTP 伺服器會繫結到 69 埠，而該埠需要特權才能存取，因此 `sudo` 必須提供：
:::

```console
sima-user@sima-user-machine:~$ sudo ~/.sima-cli/.venv/bin/sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

這個指令：

1. 下載指定 SDK 版本和板型對應的可開機映像檔。
2. 將檔案解壓縮到一個暫時的工作目錄中。
3. 啟動一個本機 TFTP 伺服器，並提供已解壓縮的啟動檔案（例如：`Image`、`boot.scr`、`.dtb` 檔案等）。

</details>

<details open>
<summary><strong>步驟 3：將 DevKit 設定為透過網路啟動 </strong></summary>

在 DevKit 連接到主機時，進行電源重啟。如果在電源重啟過程中，序列埠連接中斷，請重新連接。等待直到看到「`Hit any key to stop autoboot`」，然後按下任意鍵以進入 U-Boot 介面：

```console
... ... ...

Address in DT is		ff:ff:ff:ff:ff:ff
Address in environment is	68:e1:54:00:05:c6
eth0: ethernet@a800000 [PRIME]
Hit any key to stop autoboot:  0
sima$
```

然後在 U-Boot 終端機中執行以下指令：

```console
sima:~$ setenv boot_targets net; saveenv; boot
```

對於 Modalix **eLxr** 目標，在啟動之前也請設定 cpio 映像檔的名稱：

```console
sima:~$ setenv cpio_name simaai-image-palette-modalix.cpio.gz; setenv boot_targets net; saveenv; boot
```

這會指示 DevKit 從步驟 2 中準備好的主機 TFTP 伺服器啟動。

:::note
預設情況下，DevKit U-Boot 的設定如下：

- `ipaddr=192.168.1.20`（DevKit的乙太網路介面，多埠板上的第一個埠）。
- `serverip=192.168.1.10`（執行 TFTP 伺服器的主機）。

若要使用不同的網路，請在 U-Boot 中更新 `serverip` 和 `ipaddr`，使其與您的環境相符。請確認 DevKit 可以透過您選擇的 IP 位址連線到主機。

```console
sima:~$ setenv serverip 10.0.0.10; setenv ipaddr 10.0.0.1; saveenv; boot
```
:::

</details>

<details open>
<summary><strong>步驟 4：燒錄 eMMC。</strong></summary>

主機上的 `--netboot` Shell 支援以下指令：

- `c` — 顯示所有已連線的使用者端，以及目前正在這些使用者端上執行的韌體版本。
- `d` — 在網路上尋找 DevKit。
- `f` — 將選取的客戶端裝置的 eMMC 進行燒錄。
- `q` — 結束工作階段並停止 TFTP 伺服器。

請等待 DevKit 完成網路啟動。這可能需要幾分鐘。一旦序列主控台上顯示登入提示，則板子已準備就緒。我們建議在整個啟動過程中保持序列主控台的連接，以便觀察完整的啟動序列。

切換回主機終端，然後按 **Enter** 鍵，直到您看到 `netboot>` 提示。您可以選擇輸入 `c` 以確認 DevKit 已連接，並顯示其目前的韌體版本，然後輸入 `f` 以進行燒錄：

```console
netboot> f
```

您應該會看到類似以下的日誌：

```text
🔍 Checking SSH availability for 192.168.1.20...
✅ Board is online!
✅ SSH is available on 192.168.1.20
netboot> f
🔧 Initiating eMMC flash [...]
```

該映像檔大小約為 1.6 GB，傳輸過程大約需要幾分鐘。以下為進度範例：

```text
↦ 520093696 bytes (520 MB, 496 MiB) copied, 1 s, 515 MB/s
↦ 5368709120 bytes (5.4 GB, 5.0 GiB) copied, 163.331 s, 32.9 MB/s
```

完成燒錄後，請重新啟動 DevKit。它會從 eMMC 啟動目標版本。

:::note
**如果 DevKit 的 IP 位址在網路啟動期間發生變更**（例如，因為 DHCP 分配的位址與預設的 `192.168.1.20` 不同），則 `f` 將無法自行連線到板卡。在 DevKit 的序列主控台上找到新的 IP 位址。它會顯示在啟動記錄中，並且在網路啟動後的 Shell 中由 `ip addr` 顯示。然後明確地將其傳遞給 `f`：

```console
netboot> f <new-ip>
```
:::

</details>

<details open>
<summary><strong>疑難排解</strong></summary>

- 如果 DevKit 無法透過網路啟動，請確認主機和裝置是否位於相同的子網路中 (`192.168.1.x`)。
- 在 Modalix 搶先體驗版中，僅支援乙太網路連接埠 0 進行網路啟動。
- 在 Linux 上，請確認主機防火牆允許使用 **UDP 埠 69（TFTP）**。
- 請驗證與 DevKit 的連線。

  ```console
  modalix:~$ ping 192.168.1.10
  ```

- 如果 `f` 無法找到映像檔，請從步驟 2 重新執行 `sima-cli bootimg --netboot` 命令，以重新整理 TFTP 路徑。
- 如果在將 Modalix DevKit 轉換為 eLxr 後，序列主控台上出現與 NFS 相關的錯誤訊息，則可以安全地忽略這些訊息。

</details>
