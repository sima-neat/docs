# Пакет підтримки апаратного забезпечення.

Пакет підтримки апаратного забезпечення (BSP) — це низькорівневе програмне забезпечення, яке забезпечує запуск плати SiMa.ai після ввімкнення живлення та переводить її в придатний для використання стан у середовищі Linux. На ньому запускаються більш складні завдання, зокрема конвеєри обробки даних, вузли ROS 2 і спеціалізовані застосунки, написані мовами C/C++.

Пакет BSP для SiMa.ai містить:

- **Завантажувач** (U-Boot) — ініціалізує DRAM, зчитує дані із завантажувального носія, завантажує ядро.
- **Ядро** — ядро Linux з драйверами SiMa.ai для MLA, CVU, ISP, PCIe, мережевих інтерфейсів і блоків пам’яті на кристалі SoC.
- **Дерева пристроїв** — містять опис периферійних пристроїв, специфічних для конкретної плати (MIPI камери, GMSL2-десеріалізатори, GPIO-роз’єми, слоти M.2), щоб ядро могло їх ідентифікувати під час завантаження системи.
- **Коренева файлова система** — інструменти для користувачів, системні служби та бібліотеки SiMa.ai середовища виконання, які взаємодіють з апаратними прискорювачами, вбудованими в мікросхему.
- **Прошивки** — для процесора безпеки (tRoot) та інших допоміжних процесорів.

## Modalix BSP

Modalix BSP розроблено для Modalix DevKit, наборів для раннього доступу Modalix і плати Modalix PCIe. Вона побудована на базі [eLxr](https://elxr.org/), дистрибутива, що базується на Debian. Управління користувацьким простором здійснюється за допомогою `apt`, тому налаштування образів Modalix ближче до пакування програмного забезпечення Debian, ніж до написання рецептів Yocto. Щоб перетворити наявний Yocto DevKit на eLxr, див. [Перехід на eLxr](./tech-notes/elxr-conversion).

Вихідний шар: [swsoc-simaai-elxr-doc](https://github.com/SiMa-ai/swsoc-simaai-elxr-doc).

## Що ви можете робити з вихідним кодом BSP.

Наведений вище репозиторій стане в пригоді, коли вам потрібно:

- **Додайте спеціалізований периферійний пристрій** — створіть накладку для опису апаратного забезпечення для нової камери MIPI, сенсора GMSL2 або плати HAT.
- **Увімкніть функції ядра** — активуйте опцію ядра (наприклад, файлову систему, мережевий протокол або драйвер USB-пристрою), якої немає в стандартному образі.
- **Замініть або розширте кореневу файлову систему** — інтегруйте власний застосунок, бібліотеку або системну службу.
- **Відтворіть випуск локально** — перезберіть точну копію образу, який використовується в DevKit, для проведення аудиту або внесення змін.

Після створення власного образу завантажте його на DevKit, використовуючи один із методів, описаних у [Оновлення мікропрограми](/uk/hardware/getting-started/firmware-update).
