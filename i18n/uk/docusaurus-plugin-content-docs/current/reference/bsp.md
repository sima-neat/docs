# Пакет підтримки апаратного забезпечення.

Пакет підтримки апаратного забезпечення (BSP) — це набір низькорівневого програмного забезпечення, який забезпечує запуск плати SiMa.ai від моменту ввімкнення до отримання функціонального середовища Linux. Він є основою, на якій працюють усі вищі рівні програмного забезпечення — конвеєри обробки даних, вузли ROS 2, спеціалізовані застосунки, написані мовами C/C++.

Пакет BSP для SiMa.ai містить:

- **Завантажувач** (U-Boot) — ініціалізує DRAM, зчитує дані із завантажувального носія, завантажує ядро.
- **Ядро** — ядро Linux з драйверами SiMa.ai для MLA, CVU, ISP, PCIe, мережевих інтерфейсів і блоків зберігання даних на SoC.
- **Дерева пристроїв** — містять опис периферійних пристроїв, специфічних для конкретної плати (MIPI камери, GMSL2-десеріалізатори, GPIO-роз’єми, слоти M.2), щоб ядро могло їх ідентифікувати під час завантаження системи.
- **Коренева файлова система** — інструменти для користувачів, системні служби та бібліотеки середовища виконання SiMa.ai, які взаємодіють з апаратними прискорювачами, вбудованими в мікросхему.
- **Прошивки** — для процесора безпеки (tRoot) та інших сопроцесорів.

## Modalix BSP

Modalix BSP розроблено для Modalix DevKit, комплектів для раннього доступу Modalix і плати Modalix PCIe. Вона створена на базі [eLxr](https://elxr.org/), дистрибутива, що походить від Debian. Управління користувацьким простором здійснюється за допомогою `apt`, тому налаштування образів Modalix більше схоже на створення пакетів програмного забезпечення Debian, ніж на написання рецептів Yocto. Для користувачів, які переносять існуючий Yocto DevKit на eLxr, див. [Перетворити на eLxr](./tech-notes/elxr-conversion).

Вихідний шар: [swsoc-simaai-elxr-doc](https://github.com/SiMa-ai/swsoc-simaai-elxr-doc).

## Що ви можете робити з вихідними кодами BSP.

Наведений вище репозиторій буде корисним, коли вам потрібно:

- **Додайте спеціальний периферійний пристрій** — створіть накладку для опису апаратного забезпечення для нової камери MIPI, сенсора GMSL2 або плати HAT.
- **Увімкніть функції ядра** — активуйте опцію ядра (наприклад, файлову систему, мережевий протокол або драйвер USB-пристрою), якої немає в стандартному образі.
- **Замініть або розширте кореневу файлову систему** — додайте власний застосунок, бібліотеку або системну службу.
- **Відтворіть випуск локально** — перезберіть точну копію образу, який поставляється з DevKit, для проведення аудиту або внесення змін.

Після створення спеціалізованого образу завантажте його на DevKit, використовуючи один із методів, описаних у [Оновлення програмного забезпечення](/hardware/getting-started/firmware-update/).
