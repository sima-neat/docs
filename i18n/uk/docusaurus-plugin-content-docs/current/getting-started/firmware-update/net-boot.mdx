# Відновлення за допомогою мережевої завантажувальної системи.

Використовуйте функцію Net Boot Recovery, коли вам потрібно завантажити DevKit через мережу замість завантаження з переносного носія. Це корисно в таких випадках:

- Вам потрібно **повернутися до попередньої версії** DevKit і встановити старішу версію SDK.
- Вам потрібно встановити версію, яка **не є останньою офіційною версією** (наприклад, попередню версію `develop` або внутрішню інженерну збірку).
- Потрібно відновити плату з пошкодженою файловою системою, а SD-карти немає. Для завантаження через мережу потрібен справний U-Boot.
- Ви вводите в експлуатацію нову плату і хочете запобігти зношуванню внутрішніх пристроїв зберігання даних.
- Ви перетворюєте Modalix DevKit з Yocto Linux на eLxr, або з eLxr назад на Yocto Linux. Перегляньте [Перехід на eLxr](/hardware/reference/tech-notes/elxr-conversion), щоб дізнатися про конкретні вимоги до перетворення.

:::note
У цьому посібнику використовуються образи прошивки від SiMa.ai. Якщо ви зібрали образ самостійно, див. [Запис образу в eMMC](/hardware/deployment/flash-image).
:::

Виконайте `sima-cli bootimg --netboot`, щоб надати доступ до цільової прошивки через вбудований TFTP-сервер на хості. Якщо на DevKit або платі PCIe встановлено прошивку версії 2.1.3 чи новішої і пристрій доступний через SSH, хост може налаштувати U-Boot. Для старішої прошивки або якщо SSH недоступний, скористайтеся послідовною консоллю на кроці 3.

<details open>
<summary><strong>Крок 1. Фізичне налаштування</strong></summary>

:::note
У macOS або Ubuntu Linux використовуйте **sima-cli 2.1.21 або новішої версії**. У Windows установлюйте й запускайте `sima-cli` в Ubuntu у **Windows Subsystem for Linux (WSL)**. NetBoot безпосередньо у Windows не підтримується.

Скористайтеся терміналом хоста, щоб запустити TFTP-сервер і почати запис образу в eMMC. Радимо відкрити окрему послідовну консоль для спостереження за мережевим завантаженням, навіть якщо ви використовуєте `--devkit` і `--autoflash`. Для ручного налаштування U-Boot на кроці 3 потрібна послідовна консоль.
:::

1. Під’єднайте **Ethernet-порт DevKit** безпосередньо до хост-машини та налаштуйте мережевий інтерфейс хоста на статичну IP-адресу **192.168.1.10**. На Modalix Early Access DevKit використовуйте Ethernet-порт 0.

2. Для рекомендованого послідовного з’єднання під’єднайте **порт UART** DevKit до хоста. Установіть `sima-cli` на хості й відкрийте послідовний термінал.

   ```console
   sima-user@sima-user-machine:~$ sima-cli serial
   ```

   У Windows можна відкрити консоль за допомогою клієнта послідовного порту для Windows. Див. [Послідовне з’єднання](/hardware/getting-started/setup-serial).

3. На DevKit налаштуйте мережевий інтерфейс, встановивши для нього стандартну статичну IP-адресу **192.168.1.20**, дотримуючись інструкцій [Налаштування мережі в автономному режимі](/hardware/getting-started/standalone-mode/network).

</details>

### Хости Windows {#windows-hosts}

Плата має з’єднуватися з TFTP-сервером, що працює у WSL. У Windows 11 22H2 або новішій версії використовуйте [дзеркальний режим мережі WSL 2](https://learn.microsoft.com/en-us/windows/wsl/networking#mirrored-mode-networking) для прямого доступу з локальної мережі. Для прямого підключення через Ethernet налаштуйте статичну IP-адресу адаптера у Windows і використовуйте адресу інтерфейсу, під’єднаного до плати, як адресу TFTP-сервера. Переконайтеся, що брандмауери Windows і Hyper-V дозволяють вхідний трафік TFTP до WSL.

<details open>
<summary><strong>Крок 2. Запустіть сервер TFTP Netboot на хості.</strong></summary>

**Вимоги**

- Хост і DevKit повинні перебувати в одній фізичній мережі або бути з’єднані безпосередньо через Ethernet.
- Використовуйте з’єднання Gigabit Ethernet або швидше.
- Для завантаження образу прошивки хосту потрібен доступ до Інтернету.
- UDP-порт **69 (TFTP)** не повинен бути заблокований брандмауером хоста.

Замініть `<version>` на цільову версію прошивки (наприклад, `%platform_version%`), `<boardtype>` на `modalix` або `mlsoc`, а `<fwtype>` на `yocto` або `elxr`.

**На macOS:**

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

**В Ubuntu або в Ubuntu під WSL**

:::warning
Сервер TFTP прив’язується до порту 69, який має особливі права, тому потрібне використання команди `sudo`:
:::

```console
sima-user@sima-user-machine:~$ sudo "$(command -v sima-cli)" bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

### Налаштування NetBoot із хоста (прошивка 2.1.3 або новіша)

Якщо DevKit або плата PCIe працює з прошивкою версії 2.1.3 чи новішої і доступна через SSH, додайте `--devkit <ip>` та вкажіть поточну IPv4-адресу пристрою. Якщо пропустити цей параметр, `sima-cli` спробує знайти пристрій і запропонує вибір, якщо знайде кілька. Перед підтвердженням перезавантаження перевірте адреси пристрою й TFTP-сервера. Якщо CLI запланував перезавантаження в режим NetBoot, пропустіть крок 3.

Щоб автоматично записати образ після мережевого завантаження пристрою, також додайте `--autoflash`.

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot --devkit <ip> --autoflash
```

В Ubuntu або WSL використовуйте `sudo`, як у прикладі вище. Після завершення мережевого завантаження, коли SSH буде доступний, `--autoflash` запише образ і запланує перезавантаження з eMMC. Якщо віддалене налаштування пропущено або CLI вказує, що потрібне ручне налаштування через послідовну консоль, залиште TFTP-сервер запущеним і виконайте кроки 3 і 4.

Ця команда виконує такі дії.

1. Завантажує файли завантаження й образ для запису відповідно до вибраної прошивки та типу плати.
2. Готує файли в керованому кеші, який можна повторно використати в наступних сеансах NetBoot.
3. Запускає TFTP-сервер і надає доступ до файлів завантаження, зокрема `netboot.scr.uimg`.

### Використання раніше завантажених образів прошивки

Щоб виконати NetBoot без завантаження прошивки під час сеансу, замініть `-v <version>` на `--images <directory>` і залиште параметри типу плати та прошивки. Для eLxr помістіть у цей каталог відповідний мінімальний архів TFTP і стиснений образ eMMC (`.img.gz`). Для Yocto використовуйте архів випуску. Додайте `--delete-cache`, якщо потрібно видалити підготовлений кеш після завершення сеансу.

<details open>
<summary><strong>Крок 3. Налаштування DevKit для завантаження через мережу</strong></summary>

Пропустіть цей крок, якщо хост налаштував NetBoot за допомогою `--devkit` на кроці 2. В іншому разі виконайте наведені нижче дії через послідовну консоль.

Перезавантажте DevKit, поки він підключений до хоста через послідовний порт. Якщо під час перезавантаження послідовний порт від’єднується, під’єднайте його знову. Зачекайте, поки не з’явиться повідомлення `Hit any key to stop autoboot`, а потім натисніть будь-яку клавішу, щоб перейти до оболонки U-Boot:

```console
... ... ...

Address in DT is		ff:ff:ff:ff:ff:ff
Address in environment is	68:e1:54:00:05:c6
eth0: ethernet@a800000 [PRIME]
Hit any key to stop autoboot:  0
sima$
```

Якщо `sima-cli` вивів команди для ручного налаштування U-Boot, скористайтеся ними. В іншому разі для прямого підключення через Ethernet, описаного в кроці 1, задайте адреси плати й TFTP-сервера, а потім завантажте сценарій із хоста.

```console
sima$ setenv ipaddr 192.168.1.20
sima$ setenv serverip 192.168.1.10
sima$ tftp ${scriptaddr} ${serverip}:netboot.scr.uimg && source ${scriptaddr}
```

Для іншої мережі підставте адресу плати й доступну їй адресу TFTP-сервера, яку показує `sima-cli`.

</details>

<details open>
<summary><strong>Крок 4. Запис образу в eMMC</strong></summary>

Якщо автоматичний запис розпочався, залиште термінал хоста відкритим і збережіть мережеве з’єднання, доки CLI не повідомить, що запис завершено й перезавантаження заплановано. Якщо з’явилося запрошення `netboot>`, а плату ще потрібно прошити, скористайтеся командами нижче.

У запрошенні `netboot>` на хості доступні такі команди.

- `c` — показує клієнтів TFTP, стан з’єднання й доступні відомості про плату.
- `d` — шукає пристрої в локальній мережі.
- `f [ip]` — записує образ в eMMC підключеного клієнта. Щоб явно вибрати плату, укажіть її поточну IPv4-адресу.
- `q` — завершує сеанс і зупиняє TFTP-сервер.

Зачекайте, доки DevKit завантажиться через мережу й CLI повідомить про доступність SSH. Це може тривати кілька хвилин.

Поверніться до терміналу хоста та натисніть клавішу **Enter**, поки не з’явиться запрошення `netboot>`. За бажанням введіть `c`, щоб підтвердити, що DevKit підключено, і відобразити поточну версію його прошивки, а потім введіть `f`, щоб розпочати процес прошивання:

```console
netboot> f
```

У вас мають відображатися журнали, схожі на наступні:

```text
🔍 Checking SSH availability for 192.168.1.20...
✅ Board is online!
✅ SSH is available on 192.168.1.20
netboot> f
🔧 Initiating eMMC flash [...]
```

Розмір образу й час запису залежать від версії прошивки. Нижче наведено приклад відображення перебігу запису.

```text
↦ 520093696 bytes (520 MB, 496 MiB) copied, 1 s, 515 MB/s
↦ 5368709120 bytes (5.4 GB, 5.0 GiB) copied, 163.331 s, 32.9 MB/s
```

Після завершення запису підтвердьте перезавантаження з eMMC у CLI або перезавантажте DevKit пізніше. На DevKit виконайте `cat /etc/buildinfo` й перевірте, що встановлено цільову версію прошивки.


</details>

<details open>
<summary><strong>Усунення несправностей</strong></summary>

- Якщо DevKit не вдається завантажити через мережу, переконайтеся, що хост і пристрій знаходяться в одній підмережі (`192.168.1.x`).
- На сторінці Modalix «Ранній доступ» підтримується лише порт Ethernet 0 для завантаження по мережі.
- Переконайтеся, що брандмауер хоста дозволяє трафік через **UDP-порт 69 (TFTP)**. Для WSL також перевірте налаштування брандмауерів Windows і Hyper-V.
- Перевірте з’єднання з DevKit:

  ```console
  modalix:~$ ping 192.168.1.10
  ```

- Якщо IP-адреса DevKit зміниться під час NetBoot, `sima-cli` спробує знайти пристрій за MAC-адресою Ethernet. Якщо автоматичний пошук не вдався, введіть `d` у запрошенні `netboot>` або виконайте на платі `ip -4 addr` через послідовну консоль. Переконайтеся, що адреса належить вашій платі, а потім скористайтеся поточною адресою для запису.

  ```console
  netboot> f <actual-ip>
  ```

- Якщо `f` повідомляє, що образ eMMC не підготовлено, перевірте, чи містить архів прошивки або локальний каталог образ для запису, і повторіть команду з кроку 2.
- Якщо після перетворення Modalix DevKit на eLxr на послідовному консольному інтерфейсі з’являються повідомлення про помилки, пов’язані з NFS, їх можна безпечно ігнорувати.

</details>
