# Оновлення програмного забезпечення

Прошивка — це основне програмне забезпечення, яке працює на DevKit. Підтримка прошивки в актуальному стані є важливою для забезпечення стабільності, безпеки та доступу до нових функцій і покращень продуктивності.

## Операційні системи {#os}

SiMa.ai Modalix DevKit працюють на **eLxr Linux**, це дистрибутив, створений на основі Debian. Пристрої, відвантажені **після середини грудня 2025 року**, постачаються з попередньо встановленою eLxr. Раніші версії Modalix (відвантажені до середини грудня 2025 року) мають попередньо встановлену Yocto і їх можна перетворити на eLxr, дотримуючись інструкцій у статті [Перетворити на eLxr](/hardware/reference/tech-notes/elxr-conversion).

### eLxr Linux

eLxr — це операційна система, розроблена на базі Debian, яка забезпечує більш гнучкі можливості для розробників на платформі Modalix. Вона пропонує:

- Повноцінне керування пакетами Debian за допомогою `apt`.
- Більш розширена та зручна платформа для розробки та налагодження.
- Можливість створювати та встановлювати інструменти безпосередньо на пристрої.

### Переваги використання eLxr у Modalix.

Користувачі Modalix отримують більш зручне для розробників середовище, зокрема:

- Доступ до стандартних пакетів Debian.
- Прискорена ітерація без перехресної компіляції.
- Спрощена система керування набором інструментів
- Більш розгалужена екосистема бібліотек і фреймворків.

## Методи оновлення

Існує три підтримувані методи оновлення програмного забезпечення DevKit:

- **[Оновіть за допомогою sima-cli.](#sima-cli)** — передайте образ прошивки через мережу та автоматично запустіть оновлення на DevKit. Цей метод ідеально підходить для оновлень, які проводяться безпосередньо в місці використання пристрою.
- **[Оновіть за допомогою образу завантажувача.](#bootimage)** — створіть або відновіть завантажувальний носій для DevKit. Корисно для відновлення несправних пристроїв або налаштування кількох завантажувальних пристроїв.
- **[Оновіть за допомогою мережевої завантажувальної системи.](#netboot)** — запустіть локальний TFTP-сервер і завантажте DevKit безпосередньо через мережу, не використовуючи носії для прошивання. Ідеально підходить для відновлення, початкового налаштування або швидкої розробки ядра/файлової системи.

:::note
Будь ласка, встановіть або оновіть `sima-cli`, перш ніж продовжувати. Ця інструкція призначена для використання з останньою версією `sima-cli`.
:::

:::warning
Для оновлення Modalix DevKit з SDK 1.7 до 2.0 потрібні додаткові кроки. Зверніться до посібника [Перетворити на eLxr](/hardware/reference/tech-notes/elxr-conversion), щоб ознайомитися з процедурою перетворення.
:::

## Оновлення за допомогою sima-cli {#sima-cli}

Цей метод дозволяє розробникам оновлювати прошивку на пристрої SiMa.ai DevKit, використовуючи інструмент `sima-cli`. За допомогою цього підходу образ прошивки завантажується на хост-машину та передається на DevKit для оновлення.

Перш ніж продовжити, переконайтеся, що хост-машина може отримати доступ до DevKit через мережу. Див.:

- [Налаштування мережі в автономному режимі](/hardware/getting-started/standalone-mode/#network)
- [Налаштування віртуальної мережі в режимі PCIe](/hardware/getting-started/pcie-mode#virtual-network)

<Tabs groupId="sima-cli-source">
<TabItem value="from-devkit" label="З DevKit" default>

Розробники можуть запускати `sima-cli` безпосередньо на автономному DevKit, щоб оновити пристрій. Переконайтеся, що DevKit має активне підключення до Інтернету, а потім виконайте:

```console
modalix:~$ sima-cli update
```

На платформі MLSoC із операційною системою Yocto Linux розробники можуть також вказувати повну URL-адресу замість рядка версії, якщо вони раніше завантажили та розмістили образ на власному хості.

```console
davinci:~$ sima-cli update http://your-server/image.tar.gz
```

</TabItem>
<TabItem value="from-host" label="From Host Machine">

:::note
Цей метод підтримується лише на платформі MLSoC, яка працює під управлінням Yocto. Для пристроїв Modalix, на яких працює Linux eLxr, виконайте оновлення безпосередньо на DevKit.
:::

Використовуйте цю команду на хості:

```console
sima-user@sima-user-machine:~$ sima-cli update --ip {ip_address_of_the_devkit}
```

Ця команда також встановлює відповідну версію драйвера Linux на хості, якщо це необхідно.

Якщо ви завантажили прошивку та розмістили її десь у вашій мережі, ви можете надати URL-адресу, щоб уникнути повторного завантаження з Інтернету.

```console
sima-user@sima-user-machine:~$ sima-cli update --ip {ip_address_of_the_devkit} http://your-server/image.tar.gz
```

</TabItem>
<TabItem value="download" label="Download only">

Якщо розробник бажає завантажити лише образ прошивки та виконати оновлення за допомогою розширених, ручних інструкцій, він може зробити це, запустивши команду `sima-cli download` з URL-адресою відповідного архіву прошивки Modalix.

</TabItem>
</Tabs>

:::note
**Для оновлення системи PCIe:**

- Починаючи з версії прошивки `1.5`, віртуальний Ethernet-інтерфейс можна використовувати в режимі PCIe, що усуває необхідність у фізичному підключенні до DevKit. Це забезпечує безперебійне оновлення через наявне PCIe з’єднання.
- Для версії прошивки `1.4` або більш ранньої, необхідно встановити пряме мережеве з’єднання з DevKit. У цьому випадку під’єднайте DevKit в автономному режимі.
:::

:::note
Щоб **повернутися до попередньої версії** DevKit або встановити збірку, яка **не є останньою версією** (наприклад, попередню версію `develop` або внутрішню інженерну збірку), використовуйте натомість процедуру [Процедура мережевої завантаження](#netboot) — вона завантажує DevKit з TFTP-сервера на хості та безпосередньо записує цільове зображення в eMMC.
:::

</TabItem>

## Оновлення за допомогою образу завантажувача {#bootimage}

У деяких випадках оновлення програмного забезпечення DevKit за допомогою стандартних методів може бути неможливим або недостатнім. Це стосується таких сценаріїв, як:

- Внутрішня пам’ять DevKit пошкоджена або не вдається запустити систему.
- Вам потрібно підготувати кілька завантажувальних SD-карт або знімних дисків для розгортання.

У таких ситуаціях ви можете використовувати команду `sima-cli bootimg`, щоб завантажити та записати повний образ завантажувального диска на пристрій, що можна від’єднати (наприклад, SD-карту або NVMe накопичувач). Крім того, ви можете використовувати сторонні інструменти, такі як [BalenaEtcher](https://etcher.balena.io/).

<Tabs groupId="bootimage-method">
<TabItem value="sima-cli" label="Using sima-cli" default>

```console
sima-cli bootimg -v 2.0.0 --boardtype [modalix|mlsoc]
```

Ця команда виконує наступні дії:

1. Завантажує образ для завантаження, призначений для вказаного типу плати (`modalix` або `mlsoc`) і версії SDK.
2. Здійснює сканування вашого хоста на наявність пристроїв для знімних носіїв інформації.
3. Пропонує підтвердити, на який пристрій потрібно записати дані.
4. Записує образ завантажувача безпосередньо на вибраний пристрій.

Після завершення процесу ви можете безпечно витягти SD-карту та вставити її в DevKit. Під час наступного завантаження DevKit завантажуватиметься з нового образу.

**Важливі примітки:**

- Цю команду необхідно виконати на хості, що працює під управлінням Linux або macOS.
- Для завантаження зображення потрібне підключення до Інтернету.

</TabItem>
<TabItem value="third-party" label="Using Third-Party Tools">

Ви також можете використовувати сторонній інструмент для запису образів, наприклад, BalenaEtcher.

1. Перш за все, завантажте образ за допомогою `sima-cli`:

   Якщо розробник бажає завантажити лише образ прошивки та виконати оновлення за допомогою розширених, ручних інструкцій, він може зробити це, запустивши команду `sima-cli download` з URL-адресою відповідного архіву прошивки Modalix.

2. Розпакуйте завантажений архів:

   ```console
   tar -xvf simaai-devkit-fw-modalix-yocto-1.7.0.tar.gz
   ```

3. Використовуйте BalenaEtcher, щоб вибрати отриманий файл `.wic.gz` і скопіювати його на вашу SD-карту або USB-накопичувач.

Після запису вставте пристрій у DevKit і ввімкніть його, щоб завантажитися з образу.

</TabItem>
</Tabs>

## Оновіть за допомогою Net Boot. {#netboot}

У деяких сценаріях розробки або відновлення може бути доцільніше — або навіть необхідно — завантажувати DevKit через мережу, а не використовувати знімний пристрій, такий як SD-карта. Це особливо корисно, коли:

- Вам потрібно **повернутися до попередньої версії** DevKit і використовувати старішу версію SDK.
- Вам потрібно встановити версію, яка **не є останньою офіційною версією** (наприклад, попередню версію `develop` або внутрішню інженерну збірку).
- Вам потрібно відновити роботу пристрою, у якого пошкоджено завантажувач або файлову систему, і при цьому немає доступної SD-карти.
- Ви встановлюєте нову материнську плату і хочете запобігти зношуванню внутрішніх пристроїв зберігання даних.
- Ви перетворюєте Modalix DevKit з Yocto Linux на eLxr, або навпаки, з eLxr на Yocto Linux. Перегляньте [Перетворити на eLxr](/hardware/reference/tech-notes/elxr-conversion), щоб дізнатися про конкретні вимоги до перетворення.

У таких ситуаціях використовуйте опцію `--netboot` разом із `sima-cli bootimg`. Вона завантажує відповідне завантажувальне зображення для цільової плати, а потім передає його через вбудований TFTP-сервер на хост-машині. Потім DevKit налаштовується в U-Boot для завантаження з цього TFTP-сервера, і нове зображення записується в eMMC з хоста.

<details open>
<summary><strong>Крок 1. Фізична підготовка.</strong></summary>

:::note
Ця процедура підтримується на хостах **macOS** і **Ubuntu Linux**.

Якщо ви ще не встановили `sima-cli` на вашому хості, встановіть його, перш ніж продовжувати.

Необхідно відкрити два термінали:

1. Серійна консоль, підключена до DevKit, використовується для зміни змінних середовища U-Boot, щоб DevKit завантажувався через мережу.
2. Сеанс командного рядка на хості використовується для запуску TFTP-сервера та ініціалізації флеш-пам’яті eMMC.
:::

1. Під’єднайте **Ethernet-порт DevKit** безпосередньо до хост-комп’ютера та налаштуйте мережевий інтерфейс хоста на статичну IP-адресу **192.168.1.10**. На платі Modalix Early Access використовуйте Ethernet-порт 0.

2. Під’єднайте **UART-порт** DevKit до хоста для отримання доступу до консолі. Після встановлення `sima-cli` на хості відкрийте послідовний термінал:

   ```console
   sima-user@sima-user-machine:~$ sima-cli serial
   ```

3. На DevKit налаштуйте мережевий інтерфейс, встановивши для нього стандартну статичну IP-адресу **192.168.1.20**, дотримуючись інструкцій, наведених [тут](/hardware/getting-started/standalone-mode/#network).

</details>

<details open>
<summary><strong>Крок 2. Запустіть сервер TFTP Netboot на хості.</strong></summary>

**Вимоги**

- Хост і DevKit повинні бути підключені до однієї фізичної мережі або мати пряме з’єднання Ethernet.
- Підключення Ethernet має бути інтерфейсом Gigabit або швидшим (швидкість передачі даних має перевищувати 1000 Мбіт/с).
- Для завантаження образу прошивки хосту потрібне підключення до Інтернету.
- UDP-порт **69 (TFTP)** не повинен бути заблокований брандмауером хоста.

Замініть `<version>` на цільову версію SDK (наприклад, `2.0.0`), `<boardtype>` на `modalix` або `mlsoc`, а `<fwtype>` на `yocto` або `elxr`.

**На macOS:**

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

**На Linux:**

:::warning
Сервер TFTP прив’язується до порту 69, який має особливі права, тому потрібне використання команди `sudo`:
:::

```console
sima-user@sima-user-machine:~$ sudo ~/.sima-cli/.venv/bin/sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

Ця команда виконує наступні дії:

1. Завантажує образ для завантаження, призначений для запитуваної версії SDK і типу плати.
2. Видобуває файли та поміщає їх до тимчасової робочої директорії.
3. Запускає локальний TFTP-сервер і надає доступ до витягнутих файлів завантаження (файли `Image`, `boot.scr`, `.dtb` тощо).

</details>

<details open>
<summary><strong>Крок 3. Налаштуйте DevKit для завантаження по мережі (Netboot).</strong></summary>

Виконайте повне перезавантаження DevKit, поки він підключений до хоста через послідовний порт. Якщо під час перезавантаження з’єднання з послідовним портом обривається, відновіть його. Перед початком завантаження відбувається коротка затримка в кілька секунд — зачекайте, поки не з’явиться повідомлення `Hit any key to stop autoboot`, а потім натисніть будь-яку клавішу, щоб перейти до оболонки U-Boot:

```console
... ... ...

Address in DT is		ff:ff:ff:ff:ff:ff
Address in environment is	68:e1:54:00:05:c6
eth0: ethernet@a800000 [PRIME]
Hit any key to stop autoboot:  0
sima$
```

Потім виконайте наступні команди в оболонці U-Boot:

```console
sima:~$ setenv boot_targets net; saveenv; boot
```

Для цілей Modalix **eLxr**, також встановіть назву образу cpio перед завантаженням:

```console
sima:~$ setenv cpio_name simaai-image-palette-modalix.cpio.gz; setenv boot_targets net; saveenv; boot
```

Це дає вказівку DevKit завантажуватися з TFTP-сервера хоста, підготовленого на етапі 2.

:::note
За замовчуванням, DevKit U-Boot налаштовано таким чином:

- `ipaddr=192.168.1.20` (Ethernet-інтерфейс DevKit, перший порт на багатопортових платах).
- `serverip=192.168.1.10` (хост-машина, на якій працює сервер TFTP).

Щоб використовувати іншу мережу, оновіть значення `serverip` та `ipaddr` у U-Boot, щоб вони відповідали вашому середовищу, і переконайтеся, що DevKit може зв’язатися з хостом за вказаними IP-адресами:

```console
sima:~$ setenv serverip 10.0.0.10; setenv ipaddr 10.0.0.1; saveenv; boot
```
:::

</details>

<details open>
<summary><strong>Крок 4. Завантажте образ на eMMC.</strong></summary>

Оболонка `--netboot` на хості підтримує дві команди:

- `c` — Відобразити всіх підключених клієнтів і версію програмного забезпечення, яка зараз на них працює.
- `f` — Перепрограмуйте eMMC обраного клієнта.

Зачекайте, поки DevKit завершить процес мережевої завантаження — це може зайняти кілька хвилин. Після того, як на послідовному інтерфейсі з’явиться запрошення для входу, плата буде готова до роботи. Ми рекомендуємо тримати послідовний інтерфейс підключеним протягом усього процесу, щоб спостерігати за повним процесом завантаження.

Поверніться до терміналу хоста та натисніть клавішу **Enter**, поки не з’явиться запрошення `netboot>`. За бажанням введіть `c`, щоб підтвердити, що DevKit підключено, і відобразити поточну версію прошивки, а потім введіть `f`, щоб виконати прошивку:

```console
netboot> f
```

У вас повинні відображатися журнали, схожі на наступні:

```text
🔍 Checking SSH availability for 192.168.1.20...
✅ Board is online!
✅ SSH is available on 192.168.1.20
netboot> f
🔧 Initiating eMMC flash [...]
```

Розмір зображення становить приблизно 1,6 ГБ, а час передавання даних – кілька хвилин. Приклад відображення прогресу:

```text
↦ 520093696 bytes (520 MB, 496 MiB) copied, 1 s, 515 MB/s
↦ 5368709120 bytes (5.4 GB, 5.0 GiB) copied, 163.331 s, 32.9 MB/s
```

Після завершення процесу прошивання вимкніть і знову ввімкніть DevKit. Тепер пристрій завантажуватиметься із зазначеної версії, що зберігається в eMMC.

:::note
**Якщо IP-адреса DevKit змінилася під час мережевої завантажувальної процедури** (наприклад, тому що DHCP призначила іншу адресу, ніж стандартна `192.168.1.20`), `f` не зможе самостійно встановити з’єднання з платою. Знайдіть нову IP-адресу в послідовній консолі DevKit — вона відображається в журналі завантаження та показується командою `ip addr` в оболонці, що використовується під час мережевої завантажувальної процедури, — а потім явно передайте її команді `f`:

```console
netboot> f <new-ip>
```
:::

</details>

<details open>
<summary><strong>Усунення несправностей</strong></summary>

- Якщо DevKit не вдається завантажити через мережу, переконайтеся, що як хост, так і пристрій знаходяться в одній підмережі (`192.168.1.x`).
- На платформі Modalix Early Access для мережевої завантажувальної системи підтримується лише порт Ethernet 0.
- У Linux переконайтеся, що брандмауер хоста дозволяє використання **UDP-порту 69 (TFTP)**.
- Перевірте з’єднання з DevKit:

  ```console
  modalix:~$ ping 192.168.1.10
  ```

- Якщо `f` не зможе знайти образ, повторно виконайте команду `sima-cli bootimg --netboot` з кроку 2, щоб оновити шляхи TFTP.
- Якщо після перетворення Modalix DevKit на eLxr на послідовному консольному інтерфейсі з’являються повідомлення про помилки, пов’язані з NFS, їх можна безпечно ігнорувати.
