# Запуск плати-носія

Модуль Modalix SoM Rev 2 під’єднується до плати-носія через **260-контактний роз’єм SODIMM**
зі стандартизованим призначенням контактів і працює з будь-якою платою-носієм,
сумісною з NVIDIA Jetson Orin NX або Orin Nano.

:::warning Спершу перевірте сумісність контактів
Перш ніж з’єднувати SoM і плату-носій, перевірте електричну сумісність
їхніх контактів.
:::

:::note Передумови
SDK 2.1 або новіший зі встановленим пакетом Palette для підтримки графіки. Також
майте під рукою технічний опис SoM, технічний опис SoC і посібник Modalix SoM
Comparison Guide.
:::

## Безпечне поводження з платою

- Забезпечте належне ESD-заземлення: антистатичний браслет і ESD-захищений килимок.
- Не торкайтеся плати, коли на неї подано живлення.
- Зберігайте плату в антистатичному пакеті, перш ніж класти її на будь-яку поверхню.
- Тримайте модуль за краї; не торкайтеся мікросхем і компонентів на платі.
- Використовуйте блок живлення з комплекту постачання.
- Після ввімкнення живлення переконайтеся, що світяться всі світлодіоди індикації живлення.
- Тримайте воду та інші електропровідні рідини подалі від плати — контакт із ними може
  її пошкодити.

## Що виведено на роз’єм

Функціональна блок-схема показує, які інтерфейси виведено на роз’єм SO-DIMM
і як вони розведені всередині модуля. Використовуйте її, щоб визначити, що ваша
плата-носій може отримати від SoM.

<figure className="doc-figure doc-figure--wide">
  <img src="/img/bsp/som-block-diagram.png" alt="Функціональна блок-схема Modalix SoM Rev 2, на якій сигнали роз’єму SO-DIMM розведено до Modalix SoC" />
  <figcaption><strong>Рисунок 5.</strong> Функціональна блок-схема Modalix SoM Rev 2</figcaption>
</figure>

| Інтерфейс | На роз’ємі |
| --- | --- |
| PCIe | `PCIe0` Gen4 ×4 (лінії 0–3), `PCIe1`, `PCIe2` Gen3 ×2 |
| MIPI CSI | `MIPI CSI0`–`CSI3`, по 2 лінії кожен |
| Ethernet | `MDI` через Gigabit Ethernet PHY (SGMII до `ETH0`); `ETH1` спільно використовує `PCIe1` |
| USB | `USB2 P0`–`P2` та `USB3 P0`–`P2` через контролер USB |
| Дисплей | `HDMI` через відеопроцесор HDMI |
| Аудіо | `I2S0` (через перетворювач рівнів), `I2S1` |
| I2C | `I2C_CAM`, `I2C0`, `I2C1`, `I2C2` |
| UART | `UART0`, `UART1`, `UART2` |
| GPIO | 15× |
| SPI | `SPI0`, `SPI1` — `SPI1` мультиплексовано з QSPI-флеш-пам’яттю на модулі |
| Живлення та керування | `SYS_RESET#`, `POWER_EN`, `SHUTDOWN_REQ#`, `SLEEP/WAKE#`, `MODE_SLEEP#`, `FORCE_RECOVERY#` |

Розміщено на модулі й не виведено назовні: LPDDR5 (×64 на DDR0-1 і DDR2-3), флеш-пам’ять eMMC
(×8), світлодіоди стану та пристрої `I2C_MGMT` — EEPROM, годинник реального часу, генератор
тактових сигналів і TPM.

:::tip
`FORCE_RECOVERY#` керує SPI-мультиплексором, який перемикає між QSPI-флеш-пам’яттю на модулі
та трактом флеш-пам’яті SoC. Виведіть цей сигнал назовні, якщо хочете виконувати відновлення без
розбирання системи.
:::

## Що потребує програмної адаптації

### Працює без змін

Ці компоненти розміщено на самому SoM, і вони працюють на будь-якій платі-носії, що відповідає
стандарту призначення 260 контактів:

Пристрій SiMa Modalix · DDR · SPI-флеш-пам’ять · флеш-пам’ять eMMC · контролер USB · RTC ·
Ethernet PHY · відеопроцесор HDMI

### Залежить від плати-носія

Ці компоненти можуть потребувати налаштування або змін у програмному забезпеченні для вашої плати:

| Компонент | Примітки |
| --- | --- |
| Камери MIPI або GMSL | Див. розділ [Камери](#cameras) нижче |
| Концентратор USB | |
| Пристрій NVMe | |
| Wi-Fi / Bluetooth | |
| **UART2** | На Modalix SoM Rev 2 призначений як термінал **Secure Boot**. У системах NVIDIA цей порт є термінальним інтерфейсом — поширене джерело плутанини під час портування. |
| **UART1** | Термінал U-Boot і Linux на Modalix SoM Rev 2, під’єднаний до перетворювача FTDI UART-USB. На платі-носії NVIDIA він зазвичай за замовчуванням працює як USB OTG (USB3). Деякі плати-носії виводять UART1 на 40-контактний роз’єм. |

## Налаштування програмного забезпечення

Більшість налаштувань виконується через **дерево пристроїв** Linux, поверх якого
накладаються **оверлеї** для відмінностей конкретної плати. Саме завдяки цьому один BSP
обслуговує кілька плат-носіїв.

- [Збирання BSP з вихідного коду](../software/build-from-source.mdx) — середовище збирання,
  ядро, U-Boot, дерева пристроїв і встановлення результату.
- [Модель використання дерева пристроїв](https://docs.kernel.org/devicetree/usage-model.html)
  та [примітки щодо оверлеїв](https://docs.kernel.org/devicetree/overlay-notes.html) —
  документація основної гілки ядра.
- [Приклади оверлеїв](https://github.com/SiMa-ai/simaai-linux/tree/master/arch/arm64/boot/dts/simaai/overlays)
  у дереві ядра.

Вихідні файли оверлеїв для конкретних плат (`.dtso`) зберігаються в репозиторії BSP у
`meta-simaai/recipes-kernel/oot-dtbo/files/`.

## Камери {#cameras}

Щоб *використовувати* камеру на DevKit, виберіть один із оверлеїв, що постачаються, — див.
[Інтерфейси камер MIPI](/hardware/getting-started/standalone-mode/mipi-camera-interfaces),
де описано вибір потрібного `.dtbo` і його налаштування в U-Boot.

На власній платі-носії вам, можливо, доведеться натомість *створити* оверлей, оскільки
лінія живлення, шина I2C і регулятори відрізняються від еталонного проєкту. Зазвичай потрібні
три складники.

Керуйте лінією вимкнення живлення камери через GPIO hog — тут порт 5, GPIO 6:

```dts
&port5 {
    cam-hog0 {
        gpio-hog;
        gpios = <6 0>;          /* GPIO_ACTIVE_HIGH */
        output-high;
        line-name = "cam0_powdn";
    };
};
```

Увімкніть шину I2C, до якої під’єднано сенсор, — тут порт SIO 5, I2C #2:

```dts
&i2c52 {
    status = "okay";
    clock-frequency = <400000>;
    #address-cells = <1>;
    #size-cells = <0>;
};
```

Оголосіть шини живлення камери як регулятори з фіксованою напругою, додані до кореневого вузла
через фрагмент оверлею, щоб Linux знав, що ці шини існують і на них подано живлення.

Почніть із [прикладів оверлеїв](https://github.com/SiMa-ai/simaai-linux/tree/master/arch/arm64/boot/dts/simaai/overlays)
у дереві ядра. Керування камерою, частота PHY, DMA для другої камери, магістраль
даних і налаштування ISP тут поки що не описані.
