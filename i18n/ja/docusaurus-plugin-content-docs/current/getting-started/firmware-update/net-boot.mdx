# ネットワークブートによる復旧

リムーバブルメディアではなく、ネットワーク経由でDevKitを起動する必要がある場合は、ネットワークブートによる復旧を使用してください。これは、次のような場合に役立ちます。

- DevKit を、より古いバージョンの SDK に**ダウングレード**する必要があります。
- 最新リリース版**ではない**ビルドをインストールする必要があります（たとえば、プレリリース版の`develop`ビルドや、社内向けのエンジニアリングイメージなど）。
- 破損したブートローダーまたはファイルシステムを持つボードを復旧する必要があり、SDカードが利用できません。
- 新しいボードを立ち上げるにあたり、内部ストレージデバイスの摩耗を避けたいと考えています。
- あなたは、Yocto LinuxのModalix DevKitをeLxrに変換するか、またはeLxrからYocto Linuxに戻しています。変換に特有の前提条件については、[eLxr に変換](/hardware/reference/tech-notes/elxr-conversion)を参照してください。

:::note
このガイドでは SiMa.ai が提供するイメージを使用します。また、ボード上で U-Boot プロンプトが動作している必要があります。独自にビルドしたイメージのインストール方法は、このガイドでは説明していません。その場合は、[イメージを eMMC に書き込む](/hardware/deployment/flash-image)を参照してください。
:::

`sima-cli bootimg`と組み合わせて、`--netboot`オプションを使用します。これにより、ターゲットボード用のブートイメージがダウンロードされ、ホスト上の組み込みTFTPサーバーから提供されます。DevKit はその TFTP サーバーから起動し、`sima-cli` が新しいイメージを eMMC に書き込みます。

実行方法は 2 つあります。

- **自動。** DevKit が Linux を起動でき、ホストから SSH で接続できる場合は、1 つのコマンドでネットワークブートの設定、DevKit の再起動、eMMC への書き込みまで行えます。シリアルコンソールは不要です。[自動ネットワークブートと書き込み](#automatic)を参照してください。
- **手動。** DevKit が Linux を起動できない場合や、ホストから SSH で接続できない場合は、シリアルコンソールから U-Boot でネットワークブートを設定します。ステップ1からステップ4に従ってください。

## 自動ネットワークブートと書き込み {#automatic}

`sima-cli` 2.1.17 以降が必要です。インストールされているバージョンは `sima-cli --version` で確認できます。

1. **DevKit のイーサネットポート**を、直接またはスイッチ経由でホストに接続します。ホストから DevKit の現在の IP アドレスに到達できることを確認します（例：`ping 192.168.1.20`）。

2. `--devkit` と `--autoflash` を指定して `sima-cli bootimg` を実行します。`<version>` をターゲットとなる SDK のバージョン（例：`%platform_version%`）に、`<devkit-ip>` を DevKit の現在の IP アドレスに置き換えてください。

   **macOS の場合：**

   ```console
   sima-user@sima-user-machine:~$ sima-cli bootimg -v <version> --netboot --devkit <devkit-ip> --autoflash
   ```

   **Linux の場合：** TFTPサーバーは特権ポートである69にバインドされるため、`sudo` が必要です。

   ```console
   sima-user@sima-user-machine:~$ sudo ~/.sima-cli/.venv/bin/sima-cli bootimg -v <version> --netboot --devkit <devkit-ip> --autoflash
   ```

   このコマンドは、デフォルトで Modalix DevKit に eLxr をインストールします。Yocto の場合は `--fwtype yocto` を追加します。`--devkit` を省略すると、`sima-cli` はネットワーク上の DevKit を探し、どれを使うかを尋ねます。

3. `sima-cli` は SSH で DevKit に接続し、使用するネットワーク設定を表示します。設定を確認してから承認してください。その後、`sima-cli` は次の処理を行います。

   1. DevKit の U-Boot 環境を保存し、ホスト上の TFTP サーバーから起動するように設定します。
   2. DevKit を再起動します。実行中のアプリケーションは中断されます。
   3. DevKit がネットワークから起動し、SSH が使用できるようになるまで待ちます。
   4. イメージを eMMC に書き込みます。

   この処理には数分かかります。コマンドは実行したままにしてください。起動の様子はシリアルコンソールで確認できますが、必須ではありません。

4. `sima-cli` が `✅ Flash completed` と表示したら、`netboot>` プロンプトで `q` と入力します。`sima-cli` は保存した U-Boot 環境を DevKit に書き戻し、DevKit が再び eMMC から起動するようにします。

5. DevKit の電源を入れ直してください。eMMC からターゲットバージョンが起動します。

`sima-cli` が SSH で DevKit に接続できない場合や、U-Boot 環境を安全に変更できない場合、DevKit の変更や再起動は行いません。TFTP サーバーは動作したままで、入力すべき U-Boot コマンドが表示されることがあります。[手動ネットワークブートと書き込み](#manual)のステップ3のとおりにシリアルコンソールからネットワークブートを設定し、ステップ4のとおりに `f` と入力してください。

## 手動ネットワークブートと書き込み {#manual}

<details open>
<summary><strong>ステップ1：物理的なセットアップ</strong></summary>

:::note
この手順は、**macOS** および **Ubuntu Linux** ホストをサポートします。

ホストマシンに `sima-cli` がインストールされていない場合は、先にインストールしてから続行してください。

2つのターミナルセッションが必要です。

1. DevKit に接続されたシリアルコンソールセッション。このセッションを使用して、U-Boot の環境変数を変更し、DevKit がネットワーク経由で起動するようにします。
2. ホストのシェルセッションです。このセッションを使用して、TFTPサーバーを起動し、eMMCへの書き込みを開始します。
:::

1. **DevKitのイーサネットポート**をホストマシンに直接接続し、ホストのネットワークインターフェースを固定IPアドレス**192.168.1.10**に設定します。Modalixの早期アクセス版DevKitでは、イーサネットポート0を使用してください。

2. コンソールアクセス用に、DevKit の **UART ポート**をホストに接続します。ホストに `sima-cli` をインストールし、シリアルターミナルを開きます。

   ```console
   sima-user@sima-user-machine:~$ sima-cli serial
   ```

3. DevKitで、ネットワークインターフェースをデフォルトの固定IPアドレス**192.168.1.20**に設定します。設定方法は、[スタンドアロンモードネットワーク設定](/hardware/getting-started/standalone-mode/network)の手順に従ってください。

</details>

<details open>
<summary><strong>ステップ2：ホスト上でTFTP ネットワークブートサーバーを起動します。</strong></summary>

**要件**

- ホストとDevKitは、同じ物理ネットワーク上にあるか、または直接のイーサネットリンクで接続されている必要があります。
- イーサネット接続は、ギガビットインターフェース以上（1000Mbpsを超えるリンク速度）である必要があります。
- ホストは、ファームウェアイメージをダウンロードするためにインターネットに接続する必要があります。
- UDPポート**69（TFTP）**は、ホストのファイアウォールによってブロックされないようにしてください。

`<version>` を、ターゲットとなる SDK のバージョン（例：`%platform_version%`）に置き換え、`<boardtype>` を `modalix` または `mlsoc` に、そして `<fwtype>` を `yocto` または `elxr` に置き換えてください。

**macOS の場合：**

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

**Linux の場合：**

:::warning
TFTPサーバーは、特権ポートである69にバインドされるため、`sudo` が必要です。
:::

```console
sima-user@sima-user-machine:~$ sudo ~/.sima-cli/.venv/bin/sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

このコマンドは：

1. 要求されたSDKバージョンとボードタイプに対応する、起動可能なイメージファイルをダウンロードします。
2. ファイルを一時的な作業ディレクトリに展開します。
3. ローカルの TFTP サーバーを起動し、抽出されたブートファイル（`Image`、`boot.scr`、`.dtb`ファイルなど）を配信します。

</details>

<details open>
<summary><strong>ステップ3：DevKit をネットワークブートするように設定します。</strong></summary>

DevKit をシリアルコンソール経由でホストに接続したまま、電源を入れ直します。電源の入れ直し中にシリアルコンソールの接続が切れた場合は、再接続してください。`Hit any key to stop autoboot` と表示されるまで待ち、任意のキーを押して U-Boot シェルに入ります。

```console
... ... ...

Address in DT is		ff:ff:ff:ff:ff:ff
Address in environment is	68:e1:54:00:05:c6
eth0: ethernet@a800000 [PRIME]
Hit any key to stop autoboot:  0
sima$
```

次に、U-Boot シェルで以下のコマンドを実行します。

```console
sima:~$ setenv boot_targets net; saveenv; boot
```

Modalix **eLxr** をターゲットとする場合は、起動前に cpio イメージの名前も設定してください。

```console
sima:~$ setenv cpio_name simaai-image-palette-modalix.cpio.gz; setenv boot_targets net; saveenv; boot
```

これは、ステップ2で準備したホストのTFTPサーバーから起動するように、DevKitに指示します。

:::note
デフォルトでは、DevKit U-Boot は、以下の設定で構成されています。

- `ipaddr=192.168.1.20`（DevKitのイーサネットインターフェース、マルチポートボードの最初のポート）。
- `serverip=192.168.1.10`（TFTPサーバーが稼働しているホストマシン）。

別のネットワークを使用するには、環境に合わせて、U-Boot 内の `serverip` と `ipaddr` を更新してください。選択した IP アドレスで、DevKit がホストにアクセスできることを確認してください。

```console
sima:~$ setenv serverip 10.0.0.10; setenv ipaddr 10.0.0.1; saveenv; boot
```
:::

</details>

<details open>
<summary><strong>ステップ4：eMMCに書き込みます</strong></summary>

ホスト上の`--netboot`シェルは、次のコマンドをサポートしています。

- `c` — 接続されているすべてのクライアントと、現在それらのクライアントで実行されているファームウェアのバージョンを表示します。
- `d` — ネットワーク上の DevKit を探します。
- `f` — 選択したクライアントのeMMCにファームウェアを書き込みます。
- `q` — セッションを終了し、TFTP サーバーを停止します。

DevKit がネットワークブートを完了するまで待ちます。これには数分かかる場合があります。シリアルコンソールにログインプロンプトが表示されたら、ボードは準備完了です。完全なブートシーケンスを観察するために、シリアルコンソールを接続したままにしておくことをお勧めします。

ホスト端末に戻り、`netboot>` プロンプトが表示されるまで **Enter** キーを押します。オプションで、`c` と入力して、DevKit が接続されていることを確認し、現在のファームウェアバージョンを表示してから、`f` と入力して書き込みます。

```console
netboot> f
```

以下のようなログが表示されるはずです。

```text
🔍 Checking SSH availability for 192.168.1.20...
✅ Board is online!
✅ SSH is available on 192.168.1.20
netboot> f
🔧 Initiating eMMC flash [...]
```

このイメージのサイズは約1.6GBで、転送には数分かかります。進捗状況の例：

```text
↦ 520093696 bytes (520 MB, 496 MiB) copied, 1 s, 515 MB/s
↦ 5368709120 bytes (5.4 GB, 5.0 GiB) copied, 163.331 s, 32.9 MB/s
```

書き込みが完了したら、DevKit の電源を入れ直してください。これにより、eMMCからターゲットバージョンが起動されます。

:::note
**ネットワークブート中にDevKitのIPアドレスが変更された場合**（たとえば、DHCPによってデフォルトの`192.168.1.20`とは異なるアドレスが割り当てられた場合）、`f`は単独ではボードに到達できません。DevKitのシリアルコンソールで新しいIPアドレスを確認してください。これはブートログに表示され、ネットワークブートされたシェルで`ip addr`によって示されます。その後、それを`f`に明示的に渡してください。

```console
netboot> f <new-ip>
```
:::

</details>

<details open>
<summary><strong>トラブルシューティング</strong></summary>

- DevKit がネットワークブートに失敗した場合、ホストとデバイスの両方が同じサブネット (`192.168.1.x`) 上にあることを確認してください。
- Modalixの早期アクセス版では、ネットワークブートに利用できるのはイーサネットポート0のみです。
- Linuxでは、ホストのファイアウォールがUDPポート69（TFTP）を許可するように設定されていることを確認してください。
- DevKitからの接続を確認してください。

  ```console
  modalix:~$ ping 192.168.1.10
  ```

- `f` でイメージが見つからない場合は、ステップ2の`sima-cli bootimg --netboot` コマンドを再度実行し、TFTPパスを更新してください。
- Modalix DevKit を eLxr に変換した後、シリアルコンソールに NFS 関連のエラーメッセージが表示された場合、それらは無視しても問題ありません。

</details>
