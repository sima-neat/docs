# ネットワークブートによる復旧

リムーバブルメディアではなく、ネットワーク経由でDevKitを起動する必要がある場合は、ネットブートリカバリーを使用してください。これは、次のような場合に役立ちます。

- DevKit を、より古いバージョンの SDK に**ダウングレード**する必要があります。
- 最新リリース版**ではない**ビルドをインストールする必要があります（たとえば、プレリリース版の`develop`ビルドや、社内向けのエンジニアリングイメージなど）。
- SD カードが使えず、ファイルシステムが破損したボードを復旧する場合。ネットワークブートには、正常に動作する U-Boot が必要です。
- 新しい基板を導入するにあたり、内部ストレージデバイスの摩耗を避けたいと考えているのですね。
- あなたは、Yocto LinuxのModalix DevKitをeLxrに変換するか、またはeLxrからYocto Linuxに戻しています。変換に特有の前提条件については、[eLxr に変換](/hardware/reference/tech-notes/elxr-conversion)を参照してください。

:::note
このガイドでは SiMa.ai が提供するファームウェアイメージを使用します。自分でビルドしたイメージを使用する場合は、[イメージを eMMC に書き込む](/hardware/deployment/flash-image)を参照してください。
:::

`sima-cli bootimg --netboot` を使うと、ホストに内蔵された TFTP サーバーから対象のファームウェアを配信できます。ファームウェア 2.1.3 以降を実行している DevKit または PCIe カードに SSH で接続できる場合は、ホストから U-Boot を設定できます。古いファームウェアを使用している場合や SSH で接続できない場合は、手順 3 でシリアルコンソールを使用してください。

<details open>
<summary><strong>ステップ1：物理的なセットアップ</strong></summary>

:::note
macOS または Ubuntu Linux では **sima-cli 2.1.21 以降**を使用してください。Windows では、**Windows Subsystem for Linux (WSL)** 上の Ubuntu に `sima-cli` をインストールして実行してください。ネイティブ Windows での NetBoot には対応していません。

ホストのシェルで TFTP サーバーを起動し、eMMC への書き込みを開始します。`--devkit` と `--autoflash` を使用する場合も、進行状況の確認には別のシリアルコンソール接続を推奨します。手順 3 で U-Boot を手動で設定する場合は、シリアルコンソールが必要です。
:::

1. **DevKitのイーサネットポート**をホストマシンに直接接続し、ホストのネットワークインターフェースを固定IPアドレス**192.168.1.10**に設定します。Modalixの早期アクセス版DevKitでは、イーサネットポート0を使用してください。

2. シリアル接続を利用する場合は、DevKit の **UART ポート**をホストに接続します。ホストに `sima-cli` をインストールしたら、シリアルターミナルを開きます。

   ```console
   sima-user@sima-user-machine:~$ sima-cli serial
   ```

   Windows では、Windows 用のシリアルクライアントでコンソールを開けます。[シリアル接続](/hardware/getting-started/setup-serial)を参照してください。

3. DevKitで、ネットワークインターフェースをデフォルトの固定IPアドレス**192.168.1.20**に設定します。設定方法は、[スタンドアロンモードネットワーク設定](/hardware/getting-started/standalone-mode/network)の手順に従ってください。

</details>

### Windows ホスト {#windows-hosts}

ボードから WSL 内の TFTP サーバーにアクセスできる必要があります。Windows 11 22H2 以降では、LAN から直接アクセスできるように [WSL 2 のミラーネットワークモード](https://learn.microsoft.com/en-us/windows/wsl/networking#mirrored-mode-networking)を使用してください。イーサネットで直結する場合は、Windows でアダプターの固定 IP アドレスを設定し、そのアドレスを TFTP サーバーのアドレスとして使用します。Windows と Hyper-V のファイアウォールが WSL への受信 TFTP トラフィックを許可していることを確認してください。

<details open>
<summary><strong>手順2：ホスト上でTFTP Netbootサーバーを起動します。</strong></summary>

**要件**

- ホストとDevKitは、同じ物理ネットワーク上にあるか、または直接のイーサネットリンクで接続されている必要があります。
- ギガビット以上のイーサネット接続を使用してください。
- ホストは、ファームウェアイメージをダウンロードするためにインターネットに接続する必要があります。
- UDPポート**69（TFTP）**は、ホストのファイアウォールによってブロックされないようにしてください。

`<version>` を対象のファームウェアバージョン（例：`%platform_version%`）、`<boardtype>` を `modalix` または `mlsoc`、`<fwtype>` を `yocto` または `elxr` に置き換えてください。

**macOS の場合：**

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

**Ubuntu または WSL 上の Ubuntu の場合**

:::warning
TFTPサーバーは、特権ポートである69にバインドされるため、`sudo` が必要です。
:::

```console
sima-user@sima-user-machine:~$ sudo "$(command -v sima-cli)" bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot
```

### ホストから NetBoot を設定する（ファームウェア 2.1.3 以降）

ファームウェア 2.1.3 以降を実行している DevKit または PCIe カードに SSH で接続できる場合は、`--devkit <ip>` を追加して現在の IPv4 アドレスを指定します。このオプションを省略すると、`sima-cli` はデバイスの検出を試み、複数見つかった場合は選択を求めます。再起動を承認する前に、デバイスと TFTP サーバーのアドレスを確認してください。NetBoot への再起動が予約された場合は、手順 3 を省略します。

ネットワークブート後に自動で書き込むには、`--autoflash` も追加します。

```console
sima-user@sima-user-machine:~$ sima-cli bootimg --boardtype <boardtype> --fwtype <fwtype> -v <version> --netboot --devkit <ip> --autoflash
```

Ubuntu または WSL では、上記と同じように `sudo` を使用します。ネットワークブートが完了し、SSH 接続が可能になると、`--autoflash` がイメージを書き込み、eMMC から起動するよう再起動を予約します。リモート設定を省略した場合やシリアルコンソールでの手動設定が必要と表示された場合は、TFTP サーバーを起動したまま手順 3 と 4 に進みます。

このコマンドは次の処理を行います。

1. 指定したファームウェアとボードの種類に対応するブートファイルと書き込み用イメージをダウンロードします。
2. 次回以降の NetBoot でも再利用できる管理対象のキャッシュにファイルを準備します。
3. TFTP サーバーを起動し、`netboot.scr.uimg` などのブートファイルを配信します。

### ダウンロード済みのファームウェアイメージを使用する

実行中のファームウェアのダウンロードを省くには、ボードとファームウェアの種類を指定したまま、`-v <version>` を `--images <directory>` に置き換えます。eLxr の場合は、対応する最小構成の TFTP アーカイブと圧縮された eMMC イメージ（`.img.gz`）をそのディレクトリに置きます。Yocto の場合はリリースアーカイブを使用します。セッション終了後に準備済みのキャッシュを削除するには、`--delete-cache` を追加します。

</details>

<details open>
<summary><strong>手順 3：DevKit をネットワークから起動する</strong></summary>

手順 2 で `--devkit` を使って NetBoot を設定できた場合は、この手順を省略します。それ以外の場合は、次の手順でシリアルコンソールを使用します。

DevKit をシリアルコンソール経由でホストに接続したまま、電源を入れ直します。電源の入れ直し中にシリアルコンソールの接続が切れた場合は、再接続してください。`Hit any key to stop autoboot` と表示されるまで待ち、任意のキーを押して U-Boot シェルに入ります。

```console
... ... ...

Address in DT is		ff:ff:ff:ff:ff:ff
Address in environment is	68:e1:54:00:05:c6
eth0: ethernet@a800000 [PRIME]
Hit any key to stop autoboot:  0
sima$
```

`sima-cli` が手動設定用の U-Boot コマンドを表示した場合は、そのコマンドを使用してください。それ以外の場合は、手順 1 のイーサネット直結構成に合わせてボードと TFTP サーバーのアドレスを設定し、ホストからブートスクリプトを読み込みます。

```console
sima$ setenv ipaddr 192.168.1.20
sima$ setenv serverip 192.168.1.10
sima$ tftp ${scriptaddr} ${serverip}:netboot.scr.uimg && source ${scriptaddr}
```

別のネットワークを使用する場合は、ボードのアドレスと、`sima-cli` に表示された到達可能な TFTP サーバーのアドレスに置き換えてください。

</details>

<details open>
<summary><strong>手順 4：eMMC に書き込む</strong></summary>

自動書き込みが始まったら、書き込みが完了し再起動が予約されたと CLI に表示されるまで、ホストのターミナルとネットワーク接続を維持してください。`netboot>` プロンプトが表示され、まだ書き込みが必要な場合は、次のコマンドを使用します。

ホストの `netboot>` プロンプトでは、次のコマンドを使用できます。

- `c` — TFTP クライアント、接続状態、取得できたボード情報を表示します。
- `d` — ローカルネットワーク上のデバイスを検出します。
- `f [ip]` — 接続したクライアントの eMMC に書き込みます。現在の IPv4 アドレスを指定すると、対象のボードを直接選択できます。
- `q` — セッションを終了し、TFTP サーバーを停止します。

DevKit のネットワークブートが完了し、CLI に SSH 接続が可能になったと表示されるまで待ちます。数分かかることがあります。

ホスト端末に戻り、`netboot>` プロンプトが表示されるまで **Enter** キーを押します。オプションで、`c` と入力して、DevKit が接続されていることを確認し、現在のファームウェアバージョンを表示してから、`f` と入力してフラッシュします。

```console
netboot> f
```

以下のようなログが表示されるはずです。

```text
🔍 Checking SSH availability for 192.168.1.20...
✅ Board is online!
✅ SSH is available on 192.168.1.20
netboot> f
🔧 Initiating eMMC flash [...]
```

イメージのサイズと書き込み時間はファームウェアのリリースによって異なります。以下は進行状況の表示例です。

```text
↦ 520093696 bytes (520 MB, 496 MiB) copied, 1 s, 515 MB/s
↦ 5368709120 bytes (5.4 GB, 5.0 GiB) copied, 163.331 s, 32.9 MB/s
```

書き込みが完了したら、eMMC から起動するよう CLI の再起動プロンプトを承認するか、後で DevKit を再起動します。DevKit 上で `cat /etc/buildinfo` を実行し、対象のファームウェアバージョンを確認してください。


</details>

<details open>
<summary><strong>トラブルシューティング</strong></summary>

- DevKit がネットワークブートに失敗した場合、ホストとデバイスの両方が同じサブネット (`192.168.1.x`) 上にあることを確認してください。
- Modalixの早期アクセス版では、ネットワークブートに利用できるのはイーサネットポート0のみです。
- ホストのファイアウォールで **UDP ポート 69（TFTP）**が許可されていることを確認してください。WSL では、Windows と Hyper-V のファイアウォール設定も確認します。
- DevKitからの接続を確認してください。

  ```console
  modalix:~$ ping 192.168.1.10
  ```

- NetBoot 中に DevKit の IP アドレスが変わると、`sima-cli` はイーサネットの MAC アドレスでボードの検出を試みます。自動検出に失敗した場合は、`netboot>` プロンプトで `d` を実行するか、シリアルコンソールからボード上で `ip -4 addr` を実行します。対象のボードのアドレスであることを確認し、現在のアドレスを指定して書き込みます。

  ```console
  netboot> f <actual-ip>
  ```

- `f` の実行時に eMMC イメージが準備されていないと表示された場合は、ファームウェアアーカイブまたはローカルのイメージディレクトリに書き込み用イメージが含まれていることを確認し、手順 2 のコマンドを再実行してください。
- Modalix DevKit を eLxr に変換した後、シリアルコンソールに NFS 関連のエラーメッセージが表示された場合、それらは無視しても問題ありません。

</details>
