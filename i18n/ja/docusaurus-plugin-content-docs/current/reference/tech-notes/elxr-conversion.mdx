# eLxr に変換

このガイドでは、既存の SiMa.ai をベースとした Yocto **DevKit** を、新しい **eLxr** ランタイム環境に変換する方法と、必要に応じて Yocto に戻す方法を説明します。

:::note
eLxrプラットフォームは、SDK **2.0.0** 以降のバージョンから、**Modalix DevKit** で利用できます。

eLxr への変換には、tRoot のアップデートと、[ネットワークブート](/hardware/getting-started/firmware-update/#netboot) を使用した eMMC の再フラッシュが必要です。
:::

**eLxr** プラットフォームは、従来の Yocto 環境に代わり、SiMa.ai DevKit の新しい標準ランタイムとして機能します。
これにより、開発者にとって大きなメリットがあります。

- **簡略化された更新** — 統一されたルートファイルシステムのレイアウトと、より大きなルートファイルシステム。
- **標準パッケージマネージャー** — Debianをベースとした、継続的なパッケージ管理機能を提供する基盤。

移行前に現在の環境を確認するには、以下の簡単なチェックを行ってください。

現在、DevKit がどのファームウェアで動作しているかを確認するには、シリアル接続または SSH 経由で接続し、次のコマンドを実行します。

```bash
cat /etc/buildinfo | grep DISTRO
```

以下のいずれかが表示されるはずです。

```text
DISTRO = poky
```

または

```text
DISTRO = eLxr
```

もし`poky`を見つけた場合は、以下の手順に従って移行してください。

<details open>
<summary><strong>ステップ1：最新版のtRootにアップデートしてください。</strong></summary>

eLxr への変換を開始する前に、DevKit を最新の **tRoot** イメージに更新してください。

この更新は、tRoot（信頼されたルート）が eLxr と互換性があることを保証するために必要です。

ホストの IP アドレスを静的 IP アドレス `192.168.1.10` に設定し、DevKit が `192.168.1.20` でアクセス可能であることを確認してください（[ネットワーク設定](/hardware/getting-started/standalone-mode/#network) を参照）。

<img src="/img/media/host-cli.png" alt="Run on the host machine" width="55" style={{float: 'left', marginRight: '8px'}} />

```bash
sima-user@sima-user-machine:~$ sima-cli update --ip 192.168.1.20 2.0.0 --troot_only
```

アップデートが正常に完了したら、**DevKit の電源を入れ直して**、変更を適用してください。

</details>

<details open>
<summary><strong>ステップ2：eLxrイメージをネットブートし、eMMCに書き込みます。</strong></summary>

残りの変換プロセスでは、[Net Boot で更新](/hardware/getting-started/firmware-update/#netboot) に記載されている標準の TFTP ネットブートとフラッシュの手順を使用します。以下の eLxr に固有の値を参照して、その手順に従ってください。

- **ステップ2（TFTPサーバーの起動）：** `--boardtype modalix --fwtype elxr -v 2.0.0` を使用します。
- **ステップ3（U-Boot の設定）：** `boot` を実行する前に、`boot_targets=net` に加えて、`cpio_name=simaai-image-palette-modalix.cpio.gz` を設定します。
- **ステップ4（フラッシュ）：**`f`を`netboot>`のプロンプトに入力します。

![接続図](/img/tech-notes/conversion-diagram.png)

*接続図*

書き込みが完了し、DevKit の電源を入れ直すと、eMMC から **eLxr** がネイティブに実行されます。

</details>

<details open>
<summary><strong>ステップ3：オプション：2.0のeLxrのすぐに使えるデモ版をインストールします。</strong></summary>

お客様のバージョン1.7のDevKitには、バージョン1.7に対応したOOB（開封後すぐに使用可能）デモがあらかじめインストールされている場合があります。eLxrを使用してDevKitをバージョン2.0に変換した後、以下の手順に従ってOOBデモをアップグレードできます。

作業を進めるには、DevKitをインターネットに接続し、SSHセッションまたはシリアルコンソールを使用してアクセスしてください。

![スタンドアロンの DevKit](/img/tech-notes/conversion-devkit-standalone.png)

*スタンドアロンのDevKit*

<img src="/img/media/devkit-cli.png" alt="Run on the devkit console shell" width="55" style={{float: 'left', marginRight: '8px'}} />

```bash
modalix:~$ cd /tmp && curl -O https://tools.modalix.info/setup-oob.sh && bash setup-oob.sh
```

インストールスクリプトの実行中に、すでに以前のバージョンの OOB エクスペリエンスがインストールされている場合、デモをアップグレードするかどうかを確認するメッセージが表示されます。確認する場合は、`Yes` と入力してください。

アセットをインストールするには、インストールを承認する必要があります。インストールスクリプトでは、インストールコマンドの実行中にコードと承認 URL が表示されます。ブラウザを開き、**auth.sima.ai** リンクにアクセスし、**開発者ポータルの認証情報**でログインします。ターミナルに表示されたコードを確認して、インストールを承認してください。

</details>

<details open>
<summary><strong>Yocto に戻す（オプション）</strong></summary>

元の状態に戻すには Yocto、以下を参照 [Net Boot で更新](/hardware/getting-started/firmware-update/#netboot) 再び `--fwtype yocto`。 `cpio_name` U-Boot 変数は必須ではありません。 Yocto 対象 — 〇〇のみ `setenv boot_targets net`, `saveenv`, `boot`.

:::note
Yocto に戻す際に、**tRoot の最小バージョン要件はありません**。したがって、上記のステップ 1 は省略できます。

eLxr に変換した後、シリアルコンソールに NFS 関連のエラーメッセージが表示された場合でも、安全に無視できます。
:::

</details>

## 要約

1. 最新の **tRoot** イメージ（≥ 2.0.0）にアップデートしてください。
2. [Net Boot で更新](/hardware/getting-started/firmware-update/#netboot) を実行し、`--fwtype elxr` と eLxr `cpio_name` を使用して、eMMC に eLxr を書き込みます。
